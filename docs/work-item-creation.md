# 按工作类型新建事项

在「工作来源 → 工作类型」中，每个类型的「允许新建」默认关闭。开启后，选择该类型时，搜索框右侧显示「新建工作事项」，清单模式也提供新建入口；切到未开启的类型时隐藏入口。「全部」类型筛选和同时选择多个类型时不显示新建入口，创建位置同时遵循当前来源、空间和单个类型范围。清单显示、新建开关、别名各自保存，隐藏类型仍能同步；桌面端所有来源范围内的类型始终参与同步，不再提供类型同步开关。CLI 显式指定的类型范围继续有效。

开关按来源、类型 Key 保存，同一来源内同类型在各空间共用设置。创建时选择真实空间与类型，使用复合 Key 定位，同一类型来自多个来源时合并位置。中文名称、别名和「产品经理」等角色名称均不用于决定类型或创建资格，本机开关也不替代飞书权限。

## 创建过程

1. 选择已开启新建的空间和类型，读取飞书字段与角色配置、必填元数据和可用模板；停用模板不参与选择，只有一个可用模板时自动选中。
2. 按字段类型填写标题、说明、模板、枚举、人员、关联事项、数字、布尔值、日期和附件。按基本信息、关联信息、人员信息分组，左侧标签、右侧灰底填写框，必填星号显示红色。进入表单后并发加载人员与关联事项候选，输入时筛选已加载结果，选择后显示标签；暂不支持的必填字段会阻止创建，并提示前往飞书项目处理。
3. 核对页显示当前可见字段及最终填写值，包含恢复草稿、本地预填和远端初始值的全部有效内容，保留有效零值；正文图片直接预览。点击「确认创建」后，先通过飞书的签名上传流程发送图片字节，逐张保存返回的图片 URL 和文件 token；任一图片未上传或本机草稿未保存成功，均不发起创建。
4. 全部图片和附件就绪后，后端再次检查来源、类型开关、当前连接与账号、字段配置版本、必填项及字段范围，然后原子登记完整请求，调用 `create_workitem` 一次；多附件在取得新编号后逐份追加并回读核验。
5. 取得创建回执的新编号后，从飞书回读确认相同空间、类型、编号的事项存在，即显示已创建；不逐项比较标题、正文、人员、选项、附件等业务字段是否与提交值完全一致。清单回读失败不会将已确认创建改成失败；新事项是否属于个人来源仍由飞书规则决定。多附件创建后的追加结果独立提示，不改变事项已创建的事实，也不锁住连续创建。

### 从需求研发新建缺陷

需求研发详情的「关联缺陷」直接读取当前空间已同步到本机的缺陷及其缓存详情，通过已实测的缺陷系统字段 `_field_linked_story` 和需求编号匹配；需求反馈不显示此入口。展示和筛选不查询飞书，缺陷内容随已有工作来源同步更新；未同步事项不在列表中，缺少关联详情的缓存会提示信息尚未齐全。“与我相关”只根据本机个人待办和已确认参与人来源的归属判断，不把其他来源视为与本人无关。点击关联缺陷只显示本机缓存详情和图片，不发起详情、流程、图片或链接元数据的远端查询；未缓存的图片及流程可在飞书或常规工作清单中查看。

工作来源中已为缺陷类型开启新建时，可以从该需求打开缺陷表单，自动填入当前需求。创建表单沿用现有飞书配置读取和写入流程，并确认该系统字段仍允许关联当前空间及需求类型；配置变化时不猜测。不同需求的草稿按账号、空间、类型、需求身份和字段隔离，通用待核验入口按请求标识找回对应草稿；用户已有的修改和主动清空会保留。连续创建下一条时重新应用该需求。创建仍遵循原有确认和防重复规则；现行创建成功判定只核验事项存在及身份，不单独保证关联字段回读一致。

创建计划保留数字、日期、布尔、人员和角色等业务类型，以供提交前字段校验；实际调用创建工具时，按网关契约把每项 `field_value` 编码为字符串。数组和对象使用 JSON 字符串，已有附件 JSON 字符串不重复编码，正文字符串保留换行、缩进和末尾空格。

文件上传前逐个即时申请授权，不持久化或复用上传签名。已观测的非分片授权包含上传地址、签名和 `sign_expire_time: 0`，可不含目标单元；有效期为 `0`、缺失或 `null` 表示未声明截止时间，允许使用刚取得的授权。明确的正整数截止时间仍按 Unix 秒或毫秒校验，过期、负数及非法类型拒绝上传；上传地址白名单、资源类型和签名头校验保持生效。授权校验失败只说明具体原因，由表单统一提示尚未发起创建、文件和草稿已保留，不自动重发上传或创建。授权兼容由本机模拟回归覆盖；正文图片的真实创建与回读验收见下文，普通附件继续按其独立验收范围说明。

表单将必填元数据与完整字段配置合并，保留必填规则、默认值、选项和关联范围，并补齐可选业务字段；不能把必填接口当作完整字段列表。编号、创建/更新时间、创建/更新人、流程状态和完成/终止信息等系统维护字段不作为可选填写项补入。未知业务类型仍展示为暂不支持，未知必填类型继续阻止提交。完整配置不含网页表单的全部可见性与分组规则，因此字段范围可以完整解析，布局及角色必填规则仍以接口实际返回为限。

### 创建前核对

核对页沿用填写时的「基本信息／关联信息／人员信息」分组，每组显示项目数；字段名使用明确的文字层级与浅底标签列，右侧完整展示最终填写值，标题加重，正文与附件独占整行。窄窗口改为上下排布，长文本和图片随正文滚动，不折叠或截断核对内容。进入核对页时从顶部开始，键盘焦点移到标题，底部保留「返回编辑」与「确认创建」。

新建事项的字段不重复标记「本次新增」，空字段显示「未填写」，不将未知的飞书默认值描述成已确认的最终值。恢复草稿、本机预填、远端初始值和有效的 `0`／`false` 继续完整核对；返回编辑保留填写内容，实际提交字段范围沿用原有规则。该展示约定适用于新建，流程操作的云端值对比规则仍按其业务契约处理。

## 本地默认值

### 字段显示偏好

首次成功打开可编辑创建表单时显示一段「缺少字段可自行添加」小贴士，可关闭；展示后用稳定本机标记记住，重新打开、切换类型和软件升级不重复显示，不新增弹窗或向导。标记存储失败不阻止填写，仅本次运行内避免重复。

飞书网页有独立的新建页字段可见性、必填和布局配置。当前 MCP 的必填元数据、字段库与角色接口未提供完整网页可见性和布局，因此本机候选字段库不等同于飞书网页新建表单，也不会自动同步网页布局。表单默认显示必填项和标题／流程／说明，有内容的字段自动显示；空的可选人员字段和角色也可自行配置，不再一次铺开全部人员。「显示字段」以卡片入口展示当前数量，展开后支持搜索和基本／关联／人员分类，直接点选卡片添加或隐藏字段；必填和固定字段收在「始终显示」标签中，已有内容的可选字段标明「已填写」并锁定，已有内容须先清空才能隐藏。人员必填规则不完整时仍提示按飞书要求添加并填写。

选择按现有账号上下文、真实空间及类型保存在本机，不含来源或表单版本；同账号同空间类型跨来源共用，升级继续保留，失效字段 Key 忽略。保存失败明确提示。草稿、合法本地默认值和远端初始值有内容时自动显示，`0` 和主动填写的 `false` 均保留。无远端初始值的布尔字段不因界面默认关闭而自动启用或提交；历史草稿里的 `false` 无法与旧版自动生成值区分，保守恢复显示，避免丢弃用户内容。核对和请求覆盖可见字段及所有有效内容，不提交未启用的空可选字段；后台仍校验完整字段规则，未知必填项仍阻止创建。连续创建重新读取表单后沿用本机显示选择。

「显示字段」是表单内的展开区域，与抽屉正文共用滚动，不再为字段卡片单独限高或拦截滚轮。展开后，若区域能放进正文可视范围，仅补足被遮住的距离；若区域过长，则将入口与搜索带到正文顶部，其余选项随正文自然滚动。选字段、切换分类和搜索时不重复自动定位。标题与底部操作栏独立占位，最后一行和保存说明均可滚动至操作栏上方；抽屉遮罩及真正的下拉弹层仍按原规则隔离滚动，不带动背景清单。

本地默认值始终自动预填，不再提供预填开关；旧版关闭过预填的偏好也不再阻止应用有效默认值。只有下拉选择字段支持本地默认值：已选文字旁显示空心星标，点击保存当前选项为默认值；当前选择与已存默认一致时显示实心星标，再次点击清除，当前填写内容保留。多选按选项集合比较，不受排列顺序影响。文本、Markdown 正文、数字、布尔、日期、人员、关联及暂不支持的字段不提供默认值功能；历史非下拉默认缓存保留但不再应用。

默认值按本机数据库、连接地址、稳定的飞书用户 Key、真实空间 Key、类型 Key 和字段 Key 隔离保存。同一账号轮换 Token、相同空间与类型来自不同来源或字段中文名称改变，不会单独导致默认值丢失。读取新表单时，先恢复已编辑草稿，再为草稿中尚未保存的字段应用本地默认值；明确清空的值、`0` 和 `false` 都属于草稿内容，不被默认值覆盖。

枚举默认值按飞书选项 ID 与当前表单核对，不依赖显示名称。单选值仍存在才预填，多选值必须全部仍存在才预填；任何已保存选项被移除时，整个字段留空，不沿用其他默认值。字段类型或单选／多选规则改变时也不应用旧值，界面提示本地默认已失效。无本地默认值时，继续使用表单本身的初始化规则；本地默认值失效时不退回其他默认值。选择项以淡色标签显示，优先使用飞书返回颜色，缺少颜色时按选项 ID 稳定映射。

默认值的存储键不含软件版本，升级后继续使用同一用户数据；不把任何人的个人默认值打包到安装程序。新版本读取到的远端选项仍须通过以上有效性核对。

## 连续创建与操作并行

表单底部提供「连续创建」，默认关闭，本机保存偏好。开启后，只有当前事项已经远端回读核验为已创建，才重新读取同一空间与类型的表单并准备下一条；标题、正文、非报告人的人员、图片和附件清空，下拉框应用当前仍合法的本地默认值，其他字段使用本次重新读取的初始值。报告人重新预填为当前 Token 对应用户。创建失败或结果不确定时保留当前表单。准备下一条失败时保留已创建成功的记录，允许重试准备，不重复发送创建。

清单刷新、连接检查、类型发现、排序、流程操作和新建分别记录在途状态，各自防重与结束，不互相释放状态。手动或自动刷新期间仍可填写和创建；完整与清单布局共用相同入口规则。切换 Token、服务地址及安装更新会改变运行上下文，创建窗口或核验读取尚未结束时继续保护该上下文。

## 草稿和结果不确定

编辑草稿按本机数据库、连接地址、稳定的飞书用户 Key 和真实空间/类型保存。每次修改及时保存字段值和已选人员等显示名称，切换类型、关闭新建窗口、退出软件再打开后仍可继续，恢复时以草稿内容优先，不用默认值覆盖用户已填或已清空的字段。本机保存失败须明确提示，不能显示为已保存；创建确认后点击「完成」清理草稿，连续创建则以一次持久写入替换为下一条草稿，替换失败仍保留成功记录。同一账号轮换 Token 不丢草稿和待核验记录。

发送前在本机保存请求标识，后端也持久保存请求与核验所需内容。相同请求不再次创建；同一账号、空间和类型存在待核对请求时，不能换一个请求标识绕过。

创建已发出但回执无法识别、调用出错、远端回读失败或返回了其他事项身份时，显示「结果不确定」并保留草稿和台账。通过「核验创建记录」恢复待核对记录，不依赖新建开关、来源是否启用或重新获取字段配置；「重新核验结果」只读取远端，不重发创建。如果尚未取得编号，可在飞书确认本次新事项后填写编号，身份和创建时间核验通过后解除待核对状态，不比较字段内容。无法取得创建时间时保留不确定，早于本次提交创建的事项不得用于解除锁定。

2026-11-05 起，已知返回编号的创建只核验事项存在性与复合身份。旧版因正文格式、图片地址或其他字段差异（含附件）保留的待核验记录，也按此规则只读恢复；核验成功后解除创建锁，开启连续创建时清空上条内容并准备下一条，不重新创建旧事项。历史或中断记录涉及多附件时，单独提示在飞书核对追加结果，不比对附件内容或重发附件写入。此调整仅适用于新建事项，不改变已有事项的流程推进与字段更新核验。

已确认未进入创建业务的例外包括网关明确拒绝字段值类型的 `MCPGatewayRequestMismatch` 参数校验格式，以及本机台账观测到的创建 `ErrFieldRequired` 必填校验拒绝格式（完整必填模板、字段列表、`retriable=false` 与可选单行诊断编号）。必填拒绝提示仅按本次保存表单的字段 Key／当前请求真实空间与类型范围内的角色 ID（错误 Key 为 `role_<空间Key>_<类型Key>_<角色ID>`）映射显示名称；结果中的 `rejected_field_keys` 仅携带成功映射的本地字段 Key，历史结果缺失时默认为空。返回草稿后，这些字段自动加入「显示字段」与当前表单，并标明「本次创建必填」，无需按角色中文名称逐项适配；字段选择继续使用现有稳定偏好保存。必填观察独立保存在当前草稿，参与本地校验，进入核对、返回编辑或关闭重开后仍保留；「需核对」只列最近一次明确拒绝返回的字段，不累加历史问题，可在重新核对后清除，连续创建的新草稿不继承本次必填观察。返回草稿时自动定位至恢复提示，点击提示中的字段名称可继续定位到对应填写位置。旧草稿已有的核对字段兼容恢复，已移除字段逐项过滤，不修改全局必填元数据。未知字段安全概括，不展示远端错误原文或内部 Key；该提示只说明飞书未通过校验，不断言用户未填写，也不改写已填正文、图片或人员。

此时说明飞书未接受创建参数、事项未创建，保留台账并恢复可编辑草稿；普通工具错误、传输失败和未知回执仍保持不确定。旧版无编号且未核验的记录，只有保存的诊断严格符合该已观测格式时，才可恢复，不要求填写不存在的编号。后台枚举不消费记录；界面先可靠保存编辑草稿和自动加入的字段选择，再确认恢复并持久转为失败、释放创建锁，保存或确认失败时恢复入口持续保留，重开优先保留同次恢复后已编辑的草稿。原请求标识永久不重发，用户重新核对确认后使用新请求创建，执行时重新检查当前准入和字段配置。恢复与保存失败路径由离线回归覆盖。

已观测的真实创建回执包含 JSON 中的 `work_item_id`；取得编号后仍须回读确认事项存在及身份，不能仅凭编号显示成功。其他回执保持结果不确定，支持按编号回读核验，不扩大既有 `success` 纯文本兼容。

## Markdown 截图粘贴

新建表单的 Markdown 正文字段支持直接粘贴剪贴板截图，在光标位置显示图片，图片前后可以继续输入，单图可以独立移除；编辑与核对页都不直接展示本机图片标记。支持 PNG、JPEG 和 WebP，单张不超过 8 MB；普通文字作为纯文本粘贴，避免带入网页样式。正文提交保留首尾空行、代码缩进和硬换行空格；纯空白必填正文仍在提交前拦截。图片先保存到本机 SQLite，草稿只保存 Markdown 引用；退出软件再打开后，本机引用或已上传的 URL＋token 均可从当前账号及字段的本机缓存恢复图片。图片读取或保存失败会保留文字并提供明确提示。

粘贴和核对本身不向飞书上传。确认创建时调用 `upload_file`，传当前空间、类型、正文真实字段 Key、`resource_type=16`、文件名、MIME 和字节数，获得签名地址；再按该地址与签名执行一次图片字节 POST。非分片使用 `part_number=0`；当前单图大小限制之外或服务要求分片的情况不擅自尝试其他协议。上传结果按 `file_url` 与 `file_token` 解析，拒绝非零业务码、缺失文件标识或未完成分片结果。签名仅后端内存使用，不写数据库、日志或 IPC。

本轮只读核对的实际 MCP `update_field` 说明，要求图片使用 `![名称](file_url)<!--file_token-->`，`create_workitem` 的 `multi-text` 字段接收 Markdown。因此当前按这份连接契约保存 URL＋token 并生成正文；不会提交 `fstodo-image:`、本地磁盘路径或 data URL。每张成功后及时保存草稿，上传失败时不创建事项，保留原图和已成功引用。图片按当前账号上下文、空间、类型及字段核对归属，不能把其他上下文的图片作为当前字段附件使用。

真实图文创建的回读会将图片说明清空、上传 token 注释改为服务生成的 `image:{"uuid":"…"}` 元数据，并在紧邻正文的图片后插入段落分隔，也可能迁移图片地址。旧版曾为这些转换逐项比对图文结构及下载图片比较 SHA256；当前新建与重新核验均已移除此成功门槛，确认事项存在即可，不因富文本表示变化锁住草稿，也不为确认创建额外下载图片。图片上传、归属和草稿恢复保护继续保留。

经用户授权，在同一真实空间与类型内沿用已成功图文记录的图片及其他有效字段，仅改变测试标题和描述，分别单次验证「图片＋带空格的 token 注释」与「不带注释的标准 Markdown 图片」。两次均明确返回 `ErrFieldRequired`，唯一缺失字段为「缺陷描述」，没有返回事项编号；不是成功或结果不确定后的重发。现有证据不能区分服务端富文本解析与必填校验的内部原因，也不能将其概括为飞书不支持纯图。应用不自动补充可见正文。

另有两个既有纯图片事项的本机详情缓存，描述值均为字符串，严格只有 `![](图片地址)<!-- image:{"width":数字,"uuid":"…"} -->`，没有正文或首尾空白。它们证明已有纯图内容能被读取和展示，同时提供了空图片说明及宽度元数据的格式差异；回读不能反推创建时的完整请求。官方规范允许写入 `width`，图片 UUID 由服务生成，不复制既有事项的 UUID。随后经追加授权，仅单次验证空图片说明、同一已上传图片及原图宽度元数据的组合，不填写 UUID 或正文；当前连接仍明确以「缺陷描述」必填拒绝，未返回事项编号。因此上述三种组合均不能作为纯图片创建修复，不扩大为飞书网页或所有接口的能力结论。

按用户确认的兼容方式，能够明确识别为本产品已上传图片、图片外仅含空白的正文，仅在实际编码发送时补一个尾部零宽空格 `U+200B`，为飞书必填校验提供不可见占位；原始请求、草稿及台账正文保持原样。已有单个尾部占位不重复添加，纯文字、图文、代码内图片、转义及未知复杂格式不改写。当前创建结果不再比较占位、图片和正文内容，不全局删除不可见字符或自动重发。历史单张纯图片测试 D 已单次真实创建成功，网页图片正常加载；当时飞书回读保留了尾部占位并迁移图片地址，下载字节与本机上传原图一致，公开核验接口已将既有记录确认成功，未重发创建。

协议依据：[飞书官方上传实现](https://github.com/larksuite/meegle-cli/blob/main/internal/products/meegle/attachment/upload.go)、[附件协议](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/attachment.md)。官方最新[富文本规范](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/rich-text-editor-markdown-syntax.md)已允许标准 Markdown 图片链接，与当前 MCP 说明存在版本差异；当前实现不据此省略本连接要求的文件 token。创建接口未单独提供完整的图片示例；真实图文及单张纯图片占位记录均已按各自路径核对远端结果与网页图片加载。

本机持久化、上传调用、引用替换及格式核验继续使用虚构数据的离线模拟回归；真实验收范围包括上述图文与单张纯图片占位，未扩展为多图或普通附件的完整线上验收。后续真实创建验证仍按用户授权的测试范围执行，不自动补写可见正文，也不重发已成功或结果不确定的请求。

## 附件字段

实测缺陷字段 `multi_attachment` 的类型为 `multi-file`，按真实字段类型识别，也支持相同类型的自定义字段 Key。表单可以选择多个任意格式文件，显示名称和大小并逐份移除；单份非空且不超过 8 MB。文件字节复用本机 SQLite 文件缓存，按账号上下文、空间、类型及字段隔离，草稿只保存引用与元数据。关闭或重启后可以恢复，不要求原始文件路径继续存在；同名且内容相同的文件去重，不同名称保留。选择、移除和核对均不向飞书上传。

确认创建后，附件使用 `resource_type=15` 获取授权，再通过已校验的签名地址单次发送文件字节，保留可选的 `x-target-unit`。正文图片继续使用 16。附件成功回执须包含 `file_token`，文件 URL 可缺省；错误业务码、未知文本、缺失 token 或未完成分片均阻止创建并保留文件。已有成功回执只有在重新确认当前账号和字段后才复用。当前不处理分片上传，也不将未实测的旧 `file` 类型当作 `multi-file`。

按官方[附件协议](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/attachment.md)，`multi-file` 的 `field_value` 是附件对象数组的 JSON 字符串。每个字段在创建时先写首个文件；新编号先持久保存，再对剩余文件依次重新读取完整附件数组、原样保留飞书补充的 `uid`、URL 及未知属性、追加一份并回读核验。核验比较文件名称、MIME、大小和重复数量，允许服务端重新签发 token，不因 token 字符串变化误报失败。

单附件和多附件的字段内容一致性均不作为创建成功或旧记录恢复的门槛。多附件需要创建事项后继续追加文件，追加过程中仅对需要追加的附件字段保留独立写入检查；标题、描述、人员及其他单附件字段差异不参与此检查，也不能阻止附件追加。任一步追加写入或回读不确定时停止后续追加，并显示带事项编号的附件提示；已经确认的事项创建保持成功、释放创建锁，连续创建可准备下一条，同时保留提示。完整请求、已有编号、附件本机字节和诊断继续保存在本机台账及缓存；旧记录只读恢复涉及多附件时提示在飞书核对追加结果。相同请求和重新核验均不重发创建或附件更新。多文件简化对象一次性写入的 `unique` 限制及逐份追加方式来自官方协议；本次对真实字段配置及已有附件详情执行读取，上传、创建和追加使用虚构数据的离线模拟测试，未向真实飞书上传文件或新建事项。

## 飞书人员配置的边界

已选关联事项的名称独立按编号只读补齐：限定当前字段允许的真实空间／类型，优先读取复合身份缓存，缓存缺失才精确查询编号（每次最多50个编号、10个关联范围），独立于关联事项候选列表；跨范围同编号有歧义或范围读取未完成时保留原选择并提示，不猜测名称、不修改关联，也不发起创建或字段写入。此路径使用虚构数据离线回归，未执行真实写入。

角色使用 `list_workitem_role_config` 的真实 ID 和名称，选择结果合并为 `role_owners` 提交。飞书缺陷的内置 `issue_reporter` 和 `reporter` 角色合并为同一个人员槽，避免重复填写；用户或角色的中文名称不参与字段映射和权限判断。

报告人是人员初始化的专门规则：通过 `search_user_info` 的 `current_login_user()` 确认当前 Token 对应用户，仅为内置 `reporter` 角色或 `issue_reporter` 字段预填该用户 Key，并使用返回姓名展示；其他人员字段、修复人、测试负责人及中文同名自定义角色不预填。这个初始化不提供星标，也不保存成人员本地默认偏好。已有草稿选择或明确清空优先，用户仍可移除本人或改选；账号变化后按新 Token 用户重新计算。

人员默认候选合并当前空间已缓存事项中的人员、自己及成功精确查询过的人员，按用户 Key 去重；角色成员及负责人即使没有邮箱，只要在明确人员容器内有真实 Key 和姓名，也会进入候选，一般关联事项或空间的同形对象不会被当成人。进入表单时预加载该集合；输入姓名片段或用户 Key 只筛选已加载候选，不自动发起在线查询。关联事项按字段允许的范围分页预加载，输入时筛选已加载结果。字段加载失败时保留已选人员与草稿，可重新打开选择框重试。每个人员标签提供独立移除按钮，也可以清空整个字段。候选缓存按数据库、连接、稳定账号和空间隔离；它是已知人员集合，不能当作完整的空间通讯录或实时成员权限名单。

只读实测确认 `search_user_info` 提供精确查询，当前空间的 `list_project_team` 返回空团队列表，无法据此获取全员通讯录。界面明确提示已知候选范围；远端查询失败但本机仍有匹配项时保留候选并提示在线查询不可用，不冒充完整查询成功。

只读实测中，MCP 必填元数据只包含普通字段，角色接口只返回角色 ID 和名称，没有返回网页上「修复人／测试负责人」的必填、默认值和多选规则。全部角色都可在「显示字段 → 人员信息」中选择，空的可选角色按本机配置显示；首次打开只对接口明确返回的必填规则标红并拦截，未提供的规则在人员区提示以飞书配置为准。飞书明确拒绝某些必填项后，恢复草稿自动显示对应字段，并将已确认规则用于本次创建，不要求用户手动添加。尚未显示任何人员时也保留添加与必填规则提示。最终创建权限和人员规则由飞书校验；当前无法声称与网页表单规则完全一致。
