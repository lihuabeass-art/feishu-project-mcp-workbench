# 按工作类型新建事项

在「工作来源 → 工作类型」中，每个类型的「允许新建」默认关闭。开启后，选择该类型时，搜索框右侧显示「新建工作事项」，清单模式也提供新建入口；切到未开启的类型时隐藏入口。「全部」类型筛选和同时选择多个类型时不显示新建入口，创建位置同时遵循当前来源、空间和单个类型范围。清单显示、新建开关、别名各自保存，隐藏类型仍能同步；桌面端所有来源范围内的类型始终参与同步，不再提供类型同步开关。CLI 显式指定的类型范围继续有效。

开关按来源、类型 Key 保存，同一来源内同类型在各空间共用设置。创建时选择真实空间与类型，使用复合 Key 定位，同一类型来自多个来源时合并位置。中文名称、别名和「产品经理」等角色名称均不用于决定类型或创建资格，本机开关也不替代飞书权限。

## 创建过程

1. 选择已开启新建的空间和类型，读取飞书字段与角色配置、必填元数据和可用模板；停用模板不参与选择，只有一个可用模板时自动选中。
2. 按字段类型填写标题、说明、模板、枚举、人员、关联事项、数字、布尔值、日期和附件。按基本信息、关联信息、人员信息分组，左侧标签、右侧灰底填写框，必填星号显示红色。人员与关联事项点击即展开候选、输入自动搜索、选择后显示标签；暂不支持的必填字段会阻止创建，并提示前往飞书项目处理。
3. 核对页显示当前可见字段及最终填写值，包含恢复草稿、本地预填和远端初始值的全部有效内容，保留有效零值；正文图片直接预览。点击「确认创建」后，先通过飞书的签名上传流程发送图片字节，逐张保存返回的图片 URL 和文件 token；任一图片未上传或本机草稿未保存成功，均不发起创建。
4. 全部图片和附件就绪后，后端再次检查来源、类型开关、当前连接与账号、字段配置版本、必填项及字段范围，然后原子登记完整请求，调用 `create_workitem` 一次；多附件在取得新编号后逐份追加并回读核验。
5. 只有取得新编号并从飞书完整回读、核对复合身份及提交字段后才显示已创建。清单回读失败不会将已确认创建改成失败；新事项是否属于个人来源仍由飞书规则决定。

表单将必填元数据与完整字段配置合并，保留必填规则、默认值、选项和关联范围，并补齐可选业务字段；不能把必填接口当作完整字段列表。编号、创建/更新时间、创建/更新人、流程状态和完成/终止信息等系统维护字段不作为可选填写项补入。未知业务类型仍展示为暂不支持，未知必填类型继续阻止提交。完整配置不含网页表单的全部可见性与分组规则，因此字段范围可以完整解析，布局及角色必填规则仍以接口实际返回为限。

## 本地默认值

### 字段显示偏好

首次成功打开可编辑创建表单时显示一段「缺少字段可自行添加」小贴士，可关闭；展示后用稳定本机标记记住，重新打开、切换类型和软件升级不重复显示，不新增弹窗或向导。标记存储失败不阻止填写，仅本次运行内避免重复。

飞书网页有独立的新建页字段可见性、必填和布局配置。当前 MCP 的必填元数据、字段库与角色接口未提供完整网页可见性和布局，因此本机候选字段库不等同于飞书网页新建表单，也不会自动同步网页布局。表单默认显示必填项和标题／流程／说明，有内容的字段自动显示；空的可选人员字段和角色也可自行配置，不再一次铺开全部人员。「显示字段」以卡片入口展示当前数量，展开后支持搜索和基本／关联／人员分类，直接点选卡片添加或隐藏字段；必填和固定字段收在「始终显示」标签中，已有内容的可选字段标明「已填写」并锁定，已有内容须先清空才能隐藏。人员必填规则不完整时仍提示按飞书要求添加并填写。

选择按现有账号上下文、真实空间及类型保存在本机，不含来源或表单版本；同账号同空间类型跨来源共用，升级继续保留，失效字段 Key 忽略。保存失败明确提示。草稿、合法本地默认值和远端初始值有内容时自动显示，`0` 和主动填写的 `false` 均保留。无远端初始值的布尔字段不因界面默认关闭而自动启用或提交；历史草稿里的 `false` 无法与旧版自动生成值区分，保守恢复显示，避免丢弃用户内容。核对和请求覆盖可见字段及所有有效内容，不提交未启用的空可选字段；后台仍校验完整字段规则，未知必填项仍阻止创建。连续创建重新读取表单后沿用本机显示选择。

「显示字段」是表单内的展开区域，与抽屉正文共用滚动，不再为字段卡片单独限高或拦截滚轮。展开后，若区域能放进正文可视范围，仅补足被遮住的距离；若区域过长，则将入口与搜索带到正文顶部，其余选项随正文自然滚动。选字段、切换分类和搜索时不重复自动定位。标题与底部操作栏独立占位，最后一行和保存说明均可滚动至操作栏上方；抽屉遮罩及真正的下拉弹层仍按原规则隔离滚动，不带动背景清单。

本地默认值始终自动预填，不再提供预填开关；旧版关闭过预填的偏好也不再阻止应用有效默认值。只有下拉选择字段支持本地默认值：已选文字旁显示空心星标，点击保存当前选项为默认值；当前选择与已存默认一致时显示实心星标，再次点击清除，当前填写内容保留。多选按选项集合比较，不受排列顺序影响。文本、Markdown 正文、数字、布尔、日期、人员、关联及暂不支持的字段不提供默认值功能；历史非下拉默认缓存保留但不再应用。

默认值按本机数据库、连接地址、稳定的飞书用户 Key、真实空间 Key、类型 Key 和字段 Key 隔离保存。同一账号轮换 Token、相同空间与类型来自不同来源或字段中文名称改变，不会单独导致默认值丢失。读取新表单时，先恢复已编辑草稿，再为草稿中尚未保存的字段应用本地默认值；明确清空的值、`0` 和 `false` 都属于草稿内容，不被默认值覆盖。

枚举默认值按飞书选项 ID 与当前表单核对，不依赖显示名称。单选值仍存在才预填，多选值必须全部仍存在才预填；任何已保存选项被移除时，整个字段留空，不沿用其他默认值。字段类型或单选／多选规则改变时也不应用旧值，界面提示本地默认已失效。无本地默认值时，继续使用表单本身的初始化规则；本地默认值失效时不退回其他默认值。选择项以淡色标签显示，优先使用飞书返回颜色，缺少颜色时按选项 ID 稳定映射。

默认值的存储键不含软件版本，升级后继续使用同一用户数据；不把任何人的个人默认值打包到安装程序。新版本读取到的远端选项仍须通过以上有效性核对。

## 连续创建与操作并行

表单底部提供「连续创建」，默认关闭，本机保存偏好。开启后，只有当前事项已经远端回读核验为已创建，才重新读取同一空间与类型的表单并准备下一条；标题、正文、非报告人的人员、图片和附件清空，下拉框应用当前仍合法的本地默认值，其他字段使用本次重新读取的初始值。报告人重新预填为当前 Token 对应用户。创建失败或结果不确定时保留当前表单。准备下一条失败时保留已创建成功的记录，允许重试准备，不重复发送创建。

清单刷新、连接检查、类型发现、排序、流程操作和新建分别记录在途状态，各自防重与结束，不互相释放状态。手动或自动刷新期间仍可填写和创建；完整与清单布局共用相同入口规则。切换 Token、服务地址及安装更新会改变运行上下文，创建窗口或核验读取尚未结束时继续保护该上下文。

## 草稿和结果不确定

编辑草稿按本机数据库、连接地址、稳定的飞书用户 Key 和真实空间/类型保存。每次修改及时保存字段值和已选人员等显示名称，切换类型、关闭新建窗口、退出软件再打开后仍可继续，恢复时以草稿内容优先，不用默认值覆盖用户已填或已清空的字段。本机保存失败须明确提示，不能显示为已保存；创建确认后点击「完成」清理草稿，连续创建则以一次持久写入替换为下一条草稿，替换失败仍保留成功记录。同一账号轮换 Token 不丢草稿和待核验记录。

发送前在本机保存请求标识，后端也持久保存请求与核验所需内容。相同请求不再次创建；同一账号、空间和类型存在待核对请求时，不能换一个请求标识绕过。

创建已发出但回执无法识别、调用出错或远端回读失败/不一致时，显示「结果不确定」并保留草稿和台账。通过「核验创建记录」恢复待核对记录，不依赖新建开关、来源是否启用或重新获取字段配置；「重新核验结果」只读取远端，不重发创建。如果尚未取得编号，可在飞书查到新事项后填写编号核对，字段、身份和创建时间核验通过后解除待核对状态。无法取得创建时间时保留不确定，不把既有同名事项误认作本次创建。

创建工具的线上写回执尚未通过试建观测。本轮仅进行真实 MCP 只读能力与字段配置确认，创建写入与核验使用虚构数据的离线模拟验证；未扩大既有 `success` 纯文本兼容。当前识别 JSON 中的 `work_item_id`，其他回执保持结果不确定，支持按编号回读核验。

## Markdown 截图粘贴

新建表单的 Markdown 正文字段支持直接粘贴剪贴板截图，在光标位置显示图片，图片前后可以继续输入，单图可以独立移除；编辑与核对页都不直接展示本机图片标记。支持 PNG、JPEG 和 WebP，单张不超过 8 MB；普通文字作为纯文本粘贴，避免带入网页样式。正文提交保留首尾空行、代码缩进和硬换行空格，回读核验也不裁剪这些空白；纯空白必填正文仍在提交前拦截。图片先保存到本机 SQLite，草稿只保存 Markdown 引用；退出软件再打开后，本机引用或已上传的 URL＋token 均可从当前账号及字段的本机缓存恢复图片。图片读取或保存失败会保留文字并提供明确提示。

粘贴和核对本身不向飞书上传。确认创建时调用 `upload_file`，传当前空间、类型、正文真实字段 Key、`resource_type=16`、文件名、MIME 和字节数，获得签名地址；再按该地址与签名执行一次图片字节 POST。非分片使用 `part_number=0`；当前单图大小限制之外或服务要求分片的情况不擅自尝试其他协议。上传结果按 `file_url` 与 `file_token` 解析，拒绝非零业务码、缺失文件标识或未完成分片结果。签名仅后端内存使用，不写数据库、日志或 IPC。

本轮只读核对的实际 MCP `update_field` 说明，要求图片使用 `![名称](file_url)<!--file_token-->`，`create_workitem` 的 `multi-text` 字段接收 Markdown。因此当前按这份连接契约保存 URL＋token 并生成正文；不会提交 `fstodo-image:`、本地磁盘路径或 data URL。每张成功后及时保存草稿，上传失败时不创建事项，保留原图和已成功引用。图片按当前账号上下文、空间、类型及字段核对归属，不能把其他上下文的图片作为当前字段附件使用。

协议依据：[飞书官方上传实现](https://github.com/larksuite/meegle-cli/blob/main/internal/products/meegle/attachment/upload.go)、[附件协议](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/attachment.md)。官方最新[富文本规范](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/rich-text-editor-markdown-syntax.md)已允许标准 Markdown 图片链接，与当前 MCP 说明存在版本差异；当前实现不据此省略本连接要求的文件 token。创建接口未单独提供完整的图片示例，复用 `multi-text` 富文本约定仍需真实创建后的回读与页面核验，不能把协议调查当作线上验收。

本轮未向真实飞书上传图片，也未真实创建事项；本机持久化、上传调用及引用替换等路径使用离线模拟和自动化回归验证，不能据此声称真实上传与网页端呈现已经验收。

## 附件字段

实测缺陷字段 `multi_attachment` 的类型为 `multi-file`，按真实字段类型识别，也支持相同类型的自定义字段 Key。表单可以选择多个任意格式文件，显示名称和大小并逐份移除；单份非空且不超过 8 MB。文件字节复用本机 SQLite 文件缓存，按账号上下文、空间、类型及字段隔离，草稿只保存引用与元数据。关闭或重启后可以恢复，不要求原始文件路径继续存在；同名且内容相同的文件去重，不同名称保留。选择、移除和核对均不向飞书上传。

确认创建后，附件使用 `resource_type=15` 获取授权，再通过已校验的签名地址单次发送文件字节，保留可选的 `x-target-unit`。正文图片继续使用 16。附件成功回执须包含 `file_token`，文件 URL 可缺省；错误业务码、未知文本、缺失 token 或未完成分片均阻止创建并保留文件。已有成功回执只有在重新确认当前账号和字段后才复用。当前不处理分片上传，也不将未实测的旧 `file` 类型当作 `multi-file`。

按官方[附件协议](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/attachment.md)，`multi-file` 的 `field_value` 是附件对象数组的 JSON 字符串。每个字段在创建时先写首个文件；新编号先持久保存，再对剩余文件依次重新读取完整附件数组、原样保留飞书补充的 `uid`、URL 及未知属性、追加一份并回读核验。核验比较文件名称、MIME、大小和重复数量，允许服务端重新签发 token，不因 token 字符串变化误报失败。

只有全部提交字段及全部附件核验一致才显示成功。任一步写入或回读不确定时，保留完整草稿、已有编号和待核验记录，停止后续追加；再次提交同一请求和「重新核验结果」均不会重发创建或附件更新。用户先在飞书核对该编号、补齐缺失附件，再只读核验。多文件简化对象一次性写入的 `unique` 限制及逐份追加方式来自官方协议；本次对真实字段配置及已有附件详情执行读取，上传、创建和追加使用虚构数据的离线模拟测试，未向真实飞书上传文件或新建事项。

## 飞书人员配置的边界

角色使用 `list_workitem_role_config` 的真实 ID 和名称，选择结果合并为 `role_owners` 提交，并以详情中的 `role_members` 回读核对。飞书缺陷的内置 `issue_reporter` 和 `reporter` 角色合并为同一个人员槽，避免重复填写；用户或角色的中文名称不参与字段映射和权限判断。

报告人是人员初始化的专门规则：通过 `search_user_info` 的 `current_login_user()` 确认当前 Token 对应用户，仅为内置 `reporter` 角色或 `issue_reporter` 字段预填该用户 Key，并使用返回姓名展示；其他人员字段、修复人、测试负责人及中文同名自定义角色不预填。这个初始化不提供星标，也不保存成人员本地默认偏好。已有草稿选择或明确清空优先，用户仍可移除本人或改选；账号变化后按新 Token 用户重新计算。

人员默认候选合并当前空间已缓存事项中的人员、自己及成功精确查询过的人员，按用户 Key 去重；角色成员及负责人即使没有邮箱，只要在明确人员容器内有真实 Key 和姓名，也会进入候选，一般关联事项或空间的同形对象不会被当成人。输入姓名片段在已知候选中筛选，完整姓名、邮箱或用户 Key 同时通过飞书精确查询补充。候选结果归属于当前字段及查询，新查询失败时不允许继续选择上一查询的人员，已选人员与草稿保留。每个人员标签提供独立移除按钮，也可以清空整个字段。候选缓存按数据库、连接、稳定账号和空间隔离；它是已知人员集合，不能当作完整的空间通讯录或实时成员权限名单。

只读实测确认 `search_user_info` 提供精确查询，当前空间的 `list_project_team` 返回空团队列表，无法据此获取全员通讯录。界面明确提示已知候选范围；远端查询失败但本机仍有匹配项时保留候选并提示在线查询不可用，不冒充完整查询成功。

只读实测中，MCP 必填元数据只包含普通字段，角色接口只返回角色 ID 和名称，没有返回网页上「修复人／测试负责人」的必填、默认值和多选规则。全部角色都可在「显示字段 → 人员信息」中选择，空的可选角色按本机配置显示；只对接口明确返回的必填规则标红并拦截，未提供的规则在人员区提示以飞书配置为准。尚未显示任何人员时也保留添加与必填规则提示。最终创建权限和人员规则由飞书校验；当前无法声称与网页表单规则完全一致。
