## 筛选方案保存与默认打开 设计与实现文档

确认日期：2026-11-02。状态：功能已实现，自动化回归、浏览器交互验收与独立 checkai 已通过；尚未发版。实际验证边界见 3.3。

用户确认原文：“好，就按这样推荐方案来吧，跨版本也要保留推荐方案，先出个 $design”。本次选定的是“方案下拉”交互；跨版本需要保留的是用户显式保存的全部筛选方案及其默认绑定。

本文是本模块后续实现与验收的唯一事实来源，承接本次对话已确认的方案，并遵循 [AGENTS.md](../../AGENTS.md) 与[产品定位与演进方向](产品定位与演进方向.md)。板块三列出的待定项应在对应实现前回填，不得将示意代码中的选择直接升级为已确认业务规则。

### 原型功能点梳理

1. **筛选方案入口** — 将完整模式筛选栏左侧的静态“筛选”标签改为可点击的方案下拉入口，保留现有快捷筛选。无方案时显示“筛选方案”；已应用时显示方案名称。
2. **方案列表** — 弹层包含内置“不限条件”、已保存方案及“保存当前条件为新方案”。每个方案展示名称、条件摘要和管理入口。
3. **当前与默认标记** — 左侧勾号表示当前正在使用的已保存条件，浅绿色“默认”标签表示下次进入页面自动应用。两个标记可出现在不同方案上；默认操作直接使用“设为默认”文字，可配房子图标辅助表达。
4. **命名保存** — 将当前筛选条件命名保存。保存表单提供“设为默认”和“同时保存搜索关键词”开关，初始均关闭；保存成功后应用该方案。
5. **默认方案** — 当前账号在“我的工作”页面最多一个默认方案。用户可以在保存时设置，也可以通过已有方案的管理入口设置或取消。
6. **临时调整** — 调整已保存方案的条件后立即更新结果，并标记“已调整”。仅提供显式的“恢复原方案 / 另存为新方案 / 更新方案”来处理保存状态。
7. **方案管理** — 支持重命名和删除。重命名保持方案身份与默认关系；删除当前方案后，当前条件保留为临时筛选。
8. **默认恢复** — 启动应用或从其他页面进入“我的工作”时应用默认方案。刷新、同步、详情返回和完整／清单模式切换保留当前条件。
9. **清除与不限条件** — 现有“清除筛选”继续保留当前事项类型；“不限条件”清除全部查看限制。两者均不删除已保存方案，也不修改默认绑定。
10. **两种布局共用** — 完整模式与清单模式共用方案、默认绑定和当前筛选状态，不分别保存两套个人方案。清单模式的入口需适配现有筛选面板。
11. **跨版本保留** — 保存的方案名称、身份、完整条件、关键词保存选项和默认绑定在正常软件升级后继续恢复，应用版本与数据格式版本独立管理。
12. **零结果与失效提示** — 没有匹配事项时保留方案及已选条件；确认字段、选项或权限失效时逐项标记需要调整的位置，禁止静默放宽筛选。
13. **统一控件与弹层体验** — 使用项目主题、现代 Switch、可访问名称、键盘操作和可见焦点；复用滚动隔离机制，适配窄窗口及日间／暗黑主题。

### 板块一：模块定位

- **业务背景**：用户反复查看相同工作范围，希望一次配置、命名保存，并在以后进入“我的工作”时自动使用个人默认条件。
- **核心职责**：管理个人本机筛选方案、当前临时筛选与默认进入策略，减少重复选择；在升级后继续恢复已保存的个人体验。
- **本期交付范围**：方案下拉、命名保存、切换、更新、另存、重命名、删除及一个个人默认方案。已在工作区实现，尚未随正式版本发布。

### 板块二：核心设计决策

- **决策 1：采用方案下拉入口**
  - **背景**：页面已有事项类型导航和快捷筛选，需要在现有位置增加保存与切换能力。
  - **方案**：使用红框位置的下拉按钮，方案在弹层集中展示；本期不采用原型中的“快捷方案栏”备选布局。完整模式保留现有快捷条件，清单模式复用相同的方案能力。
  - **调研依据**：[Jira 保存搜索](https://support.atlassian.com/jira-software-cloud/docs/what-is-a-saved-search/)、[Linear 自定义视图](https://linear.app/docs/custom-views)与[默认首页](https://linear.app/docs/account-preferences)、[ClickUp 保存筛选](https://help.clickup.com/hc/en-us/articles/6311659064983-Saving-view-filters)与[默认视图](https://help.clickup.com/hc/en-us/articles/6310067436695-Set-a-default-view)、[飞书表格筛选视图](https://www.feishu.cn/hc/zh-CN/articles/360049067640-%E5%9C%A8%E8%A1%A8%E6%A0%BC%E4%B8%AD%E4%BD%BF%E7%94%A8%E7%AD%9B%E9%80%89%E8%A7%86%E5%9B%BE?slug=true)。这些是本次交互取舍的来源，FSTODO 的最终规则以本文为准。

- **决策 2：分开管理已保存方案、当前状态与默认绑定**
  - **背景**：用户会临时查找其他事项，不应因一次临时调整而改变日常方案。
  - **方案**：已保存方案是可复用的条件集合；当前状态可临时偏离方案；默认绑定只决定下次进入使用哪个已保存方案。采用明确的保存、更新、设为默认操作，不自动覆盖方案。

- **决策 3：保存条件，按当前缓存重新计算结果**
  - **背景**：工作事项会随同步变化，用户需要持续查看符合条件的工作。
  - **方案**：保存事项类型、空间、所属项目、流程类型、节点、状态；关键词通过独立开关决定是否保存。方案不固定某一批事项 ID 或结果数量，同步后在当前缓存上重新筛选。关键词开关默认关闭。

- **决策 4：默认恢复只发生在进入页面时**
  - **背景**：需要稳定的进入体验，也要保留正在进行的临时查看。
  - **方案**：启动或从其他页面进入“我的工作”时应用默认。手动切换方案只影响当前结果；设置默认后提示下次进入生效。刷新、同步、详情返回和两种布局切换均不重新应用默认。

- **决策 5：跨版本保留作为必验能力**
  - **背景**：用户明确追加“跨版本也要保留”，仓库也要求本机偏好使用稳定位置与身份。
  - **方案**：方案及默认绑定落在稳定用户数据位置，存储命名空间不包含应用版本号、构建号或 commit。数据格式版本独立管理，变化时提供兼容读取或迁移；应用升级与无关配置变化不成为失效条件。具体载体及格式见 U2，账号身份见 U1。

- **决策 6：两种布局共用一套方案和条件**
  - **背景**：现有完整模式与清单模式已共用 `WorkFilters`。
  - **方案**：方案保存、默认绑定、应用与调整判断均采用同一业务状态；布局切换只改变展示方式。顶部标签和侧栏类型入口与方案中的事项类型保持一致，不能出现结果与导航各自使用不同条件。

- **决策 7：零结果不等于条件失效**
  - **背景**：某个项目或节点暂时没有事项，仍可能是用户长期关心的范围。
  - **方案**：保留零结果条件与已知名称。确认远端字段、选项或权限失效后逐项标记需要调整，不静默删除限制，也不重置整个方案。有效性证据与节点／状态名称变化的处理方式见 U3。

### 板块三：业务结论与待定议题记录

#### 3.1 已对齐的业务与架构结论

- **1. 个人默认范围**：以账号和“我的工作”页面为范围，一个账号在该页面最多一个默认方案；顶部显示来源不分割出多套默认绑定。
- **2. 默认表达**：使用“设为默认”文字操作和“默认”标签，房子图标仅作辅助；不引入星标收藏机制。
- **3. 当前与默认独立**：应用 B 时可以保持 A 为默认；设置 B 为默认不强制切换当前结果，下一次进入使用 B。
- **4. 更新与另存独立**：临时调整显示“已调整”；更新写回原方案，另存生成新方案并应用，新建时“设为默认”初始关闭。更新默认方案后，下一次进入使用更新后的条件。
- **5. 进入与运行过程独立**：启动或从其他页面进入时恢复默认；同步、刷新、详情返回和布局切换维持当前条件。切换事项类型属于当前筛选调整，不自动改写方案。
- **6. 清除行为**：“清除筛选”保留当前事项类型；“不限条件”清除全部查看限制。两者只改变当前查看，不删除方案或默认绑定。
- **7. 方案删除与重命名**：重命名沿用稳定方案身份与默认引用；删除当前方案后保留当前条件为临时筛选。删除或取消默认后，下次进入使用不限条件，不自动选择其他方案。
- **8. 显示来源独立**：保存方案不包含顶部“显示来源”。应用方案只作用于当前显示范围，不更改刷新目标或来源配置；主动切换来源沿用现有筛选清理规则，默认绑定保持原值，下次进入页面再应用默认。
- **9. 保存字段边界**：本期保存现有事项类型、空间、所属项目、流程类型、节点、状态，搜索关键词默认不保存，可显式开启。窗口、主题、同步配置不属于方案内容。
- **10. 个人数据归属**：方案为仅本机个人偏好，不写入飞书业务数据，不表示跨设备同步；不同账号隔离。
- **11. 跨版本保持**：用户保存的全部方案及默认绑定均需保留，不能只保留当前方案或默认方案；升级后可继续管理和应用。
- **12. 失效处理**：零结果和缓存暂缺不构成删除条件的证据；真实失效按项处理，保留其他条件，禁止静默扩大匹配范围。

### 板块四：系统边界与外部解耦

- **核心定位切分**：本模块属于个人查看体验层，负责用户偏好及列表过滤；事项数据、权限和业务规则仍由飞书项目掌握。
- **数据/调用边界**：保存的是本机条件，应用时筛选已取得的缓存。保存、更新、切换或设置默认不应触发远端业务写入，也不改变来源查询、同步范围、刷新目标与工作流推进规则。
- **显示来源边界**：顶部显示来源决定当前显示范围及相关刷新目标，方案在该范围内生效。应用后零结果时展示当前条件与范围，允许用户主动调整来源或筛选。
- **布局边界**：完整模式和清单模式使用同一套业务状态；原型中两个候选设计的独立演示状态不能作为正式产品分开存储的依据。
- **AI 与共享边界**：本期为确定性的可视化选择和本机偏好，不增加 AI 对话、自动推荐、团队共享或跨设备方案同步能力。
- **交付边界**：本文落定本次确认的产品规则与验收门槛。已有交互示意的浏览器验证不等同于真实存储、升级迁移或正式功能验收通过。

### 板块五：底层驱动与数据模型

以下模型对应已实现的业务语义与存储结构。账号识别、表名、序列化字段、格式号及 IPC 的实施选择见 U1、U2。

- **核心模型 1：已保存筛选方案**

  | 概念字段 | 类型／语义 | 约束 |
  | --- | --- | --- |
  | 稳定方案 ID | 不透明的稳定标识 | 不依赖名称、排序、来源或应用版本；重命名沿用原 ID |
  | 方案名称 | 字符串 | 用于展示和管理；具体长度及同名规则见 U5 |
  | 账号归属 | 稳定账号身份 | 不同账号隔离，具体获取方式见 U1 |
  | 筛选条件 | 现有 `WorkFilters` 的已保存条件 | 保存条件语义，不保存当前结果快照或事项 ID 集合 |
  | 是否包含关键词 | 布尔值 | 默认关闭；关闭时不把临时关键词写入已保存条件 |

- **核心模型 2：页面默认绑定**

  | 概念字段 | 类型／语义 | 约束 |
  | --- | --- | --- |
  | 账号归属 | 与方案相同的稳定账号身份 | 不以工作来源或显示名称分裂同一账号的默认设置 |
  | 页面范围 | “我的工作” | 本期唯一确定的适用页面；完整／清单模式不构成两个页面范围 |
  | 默认方案 ID | 稳定方案 ID 或空 | 一个账号、一个页面最多一个引用；引用同账号的已保存方案；重命名不改变引用，删除默认方案时取消绑定 |

- **核心模型 3：当前运行状态**
  - 当前应用的方案身份可为空，当前 `WorkFilters` 可与已保存条件不同。
  - “已调整”由当前条件与对应方案的已保存条件比较得出，不能反过来作为自动保存指令。
  - 未保存的条件与临时关键词不因页面关闭、默认恢复或应用版本变化而被推断成已保存方案。
  - 默认恢复从已保存方案读取，不能用上次退出时的临时条件替代；不含关键词方案对当前搜索输入的处理见 U4。

- **核心模型 4：数据格式版本与迁移**
  - 数据格式版本独立于软件发布版本，不将应用版本号、构建号或 commit 写入方案命名空间。
  - 格式变更提供兼容读取或迁移，保留方案 ID、账号归属、名称、条件、关键词选项及默认引用。
  - 升级后重复启动不重复创建方案，不把默认绑定重置为另一个方案。
  - 无格式变化的软件升级，不因版本变化触发偏好清空。

现有 [WorkFilters](../../frontend/src/workFilters.ts) 的字段与映射如下，不新增本期未讨论的筛选维度：

| 现有字段 | 当前类型 | 本模块用途 |
| --- | --- | --- |
| `type` | `string[]` | 事项类型条件，恢复时同步顶部标签与侧栏 |
| `space` | `string[]` | 空间条件，沿用真实空间 Key |
| `project` | `string[]` | 所属项目条件，沿用现有空间／项目复合值语义 |
| `flowKind` | `string[]` | 流程类型条件 |
| `nodeName`、`stateName` | `string[]` | 当前节点、状态条件；持久身份与改名问题见 U3 |
| `query` | `string` | 开启关键词保存时纳入持久条件；关闭时属于临时搜索 |
| `spaceLabel`、`typeLabel`、`projectLabel` | `Record<string, string>` | 已选值的可读名称，不充当业务身份或方案 ID |

多选沿用现有筛选语义：同一字段内多个值取并集，不同字段之间取交集，空集合表示不限制。保存和恢复不能把多选条件降为单选。

### 板块六：避坑指南与防御性设计

- ❌ **将最后一次临时筛选自动覆盖为默认**。
  - ✅ 默认引用已保存方案；临时调整只改变当前结果，“更新方案”才写回条件。
- ❌ **仅保留默认方案，升级后丢失其他已保存方案**。
  - ✅ 跨版本验收覆盖全部方案及其稳定身份、条件、关键词选项和默认关系。
- ❌ **把应用版本、构建号、commit、来源显示名或无关配置指纹放入偏好命名空间**。
  - ✅ 使用稳定用户数据位置和身份；数据格式单独版本化，变化时兼容读取或迁移。同一账号不能因凭证轮换被直接当成新用户，账号判定方案按 U1 回填。
- ❌ **从旧的临时筛选缓存推断用户已经保存过方案或指定过默认**。
  - ✅ 继续忽略历史临时缓存；新增方案只承接显式保存的内容。
- ❌ **用结果数为零或候选列表暂缺判断条件已失效**。
  - ✅ 保留条件与名称；有可靠失效证据后逐项提示，不静默删除限制，不全量重置。
- ❌ **将显示名称当身份，或将名称补齐、多选集合顺序变化误认为用户调整了条件**。
  - ✅ 方案与默认使用稳定 ID；条件按业务选择语义比较。标签只帮助阅读，节点与状态名称的特殊问题按 U3 处理。
- ❌ **恢复方案时逐个调用带联动清理的筛选操作，导致保存的项目、节点或状态消失**。
  - ✅ 校验并恢复同一套条件，确保最终生效值与已保存组合一致，同时保留现有手动筛选联动。
- ❌ **在完整／清单模式分别持久化方案，或在同步结束后重新压回默认条件**。
  - ✅ 两种布局共享业务状态；默认恢复使用页面进入语义，运行过程维持当前条件。
- ❌ **套用交互示意的演示存储或校验常量，宣称已实现真实跨版本保留**。
  - ✅ 正式存储、身份、迁移与名称规则按待定项回填；通过 K10–K12 的真实用户数据验证后再确认交付。
- ❌ **只阻止滚轮冒泡，或通过裁切内容隐藏滚动条**。
  - ✅ 复用 `useScrollIsolation`、`scroll-isolation-boundary`、原生非 passive 滚轮监听与 CSS `overscroll-behavior`；保留列表内部滚动，正确清理监听并验证关闭后的外层滚动恢复。
- ❌ **新增原生外观复选框、孤立主题色或只验证切换完成后的静态画面**。
  - ✅ 使用项目统一 Switch 和主题入口；验证键盘、焦点、禁用、减少动态效果、Portal 弹层及主题切换过程，保持全应用隐藏原生滚动条的规则。
