# 节点筛选与来源范围

同一事项可以同时处于多个并行节点。“前端代码合入 / 后端代码合入”是列表展示文案，不是单个节点名称，不能直接作为新筛选候选。

## 节点范围

- “我的待办”使用该来源保存的本人节点，悬停说明为“我的待办节点”。
- “我参与的需求”与“全部来源”使用事项完整详情的全部当前节点，悬停说明为“事项当前节点”。
- 尚无本人节点上下文的旧记录继续显示事项节点，悬停说明为“事项当前节点”；混合范围使用“当前节点”。状态流不使用过期的本人节点。
- 完整模式、清单模式和详情中的节点行直接展示节点名称，不重复显示范围前缀；两种模式的筛选入口统一称为“节点”，已选条件统一使用“节点”前缀。范围说明只保留在悬停提示中。
- 来源只改变清单范围与展示投影，不改变事项身份，也不把本人节点覆盖到共享事项摘要。

## 筛选与计数

候选来自缓存详情的结构化当前节点数组，逐个名称去重。选择一个节点时匹配包含该节点的事项；同一筛选内多选取并集，不同维度取交集。列表可以继续用斜线连接多个节点，但筛选不按斜线拆分，真实节点名称中的斜线保留原义。

节点数量表示包含该节点的事项数。同一事项内重复返回的节点名称只计一次；同一事项命中多个选中节点、同时属于多个来源时，也只显示一行。事项身份继续使用“空间 Key＋类型 Key＋事项编号”，不同空间或类型的同号事项分别保留。多个并行节点覆盖全部结果时仍提供独立候选，各节点数量可以重叠，不能相加推算事项总数。

完整模式和清单模式共用筛选与计数规则。已选但没有结果的条件继续显示零计数，供用户取消。

## 旧缓存与方案

当前节点数组直接从已有完整详情缓存派生，不新增远端请求、不重置数据库或筛选方案。缺失结构化详情时只将旧摘要当作一个完整名称，不猜测分隔符；明确的空节点数组不回退到旧摘要。

读取缓存时，节点摘要与流程类型同步采用已有详情中的当前节点，节点改名、推进或清空后不继续展示旧摘要。原摘要未提供节点但已有详情包含节点时可直接恢复；明确的远端节点流类型也能纠正旧状态流摘要。后端流程类型查询按这份最终结果筛选，并在筛选后分页。

旧方案中已经保存的组合文案继续按原来的精确展示值匹配，标为“原条件”，并保留准确计数和取消入口；未选中的组合文案不再作为新候选。真实名称含展示分隔符时，新选择使用带命名空间的独立节点值，界面和方案摘要仍展示原名称；它只匹配该节点，不误匹配恰好同文案的并行组合。旧值的含义不随空间、状态或其他候选的变化而重新解释。仅切换来源、布局或加载方案不会改写已保存条件。

## 回归入口

- `backend/tests/node_filter_cache.rs`：旧详情缓存重新打开、斜线名称、重复名称、推进与清空、多来源交替及唯一事项、缺失或旧流程类型恢复、流程筛选与分页。
- `backend/src/api.rs`：共同事项的本人节点与完整节点保持各自范围，重复同步无业务更新。
- `frontend/src/model.test.ts`：独立节点、多选并集、准确计数、旧组合兼容、真实名称优先与空节点。
- `frontend/src/App.nodes.test.tsx`：完整／清单模式、来源切换、不同空间同号事项、旧方案恢复及不自动改写。
- `frontend/src/filterSchemes.test.tsx`：含分隔符的独立节点条件经过保存、恢复后仍匹配原节点，摘要不显示内部标识。
