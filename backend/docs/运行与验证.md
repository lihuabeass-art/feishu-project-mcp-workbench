# 运行与验证

本文与代码行为逐条对应；命令均在 `backend/` 目录下执行。

## 1. 构建

```powershell
cargo build                      # 产物 target/debug/fstodo.exe
```

工具链：`rustc 1.88.0` / `cargo 1.88.0`，Windows MSVC（`link.exe` 来自 VS BuildTools）。
SQLite 走 `rusqlite` 的 `bundled` feature，自带编译，无系统依赖。

## 2. 配置与凭证

| 项 | 取值 | 依据 |
|---|---|---|
| 配置文件 | `%APPDATA%\FSTODO\config.toml`（不存在则用内置默认值） | 凭证与个人路径不进仓库 |
| 缓存库 | `%LOCALAPPDATA%\FSTODO\fstodo.db`（`--db` 或 `db_path` 可覆盖） | 同上 |
| 端点 | `https://project.feishu.cn/mcp_server/v1`，强制 https | 凭证走 `X-Mcp-Token` 请求头，明文 HTTP 会裸奔 token |
| 凭证 | 环境变量 `FSTODO_MCP_TOKEN` 优先，其次 `token_file` | token 不允许出现在配置文件、命令行参数、日志与数据库业务表中 |
| 台账保留 | 默认 `sync_run_retention = 0`（永久保留） | 桌面端始终保留；CLI 可手工用正数限制已结束记录数 |
| 流程写开关 | `workflow_enabled = true`（**默认开启**） | CLI 可设为 false 关闭流程写入，执行仍要求 `--yes`；桌面端默认开启并要求界面确认 |

防呆（代码强制，非口头约定）：

- 配置文件出现未知键 → 报配置错误（`deny_unknown_fields`）；
- `token_file` 位于当前工作目录之内 → 拒绝读取（防随仓库提交）；
- `SecretToken` 的 `Debug`/`Display` 只输出 `***（长度 N 字符）`，取值原文只在构造 HTTP 头时触碰一次。

## 3. 命令与退出码

| 命令 | 联网 | 说明 |
|---|---|---|
| `fstodo config` | 否 | 打印生效配置（不含任何凭证） |
| `fstodo doctor` | 否 | 配置/路径/缓存库/凭证来源自检 |
| `fstodo check` | 是 | 建立 MCP 会话（`initialize`）并回读服务端信息；每次强制新建会话，结果代表「当下」 |
| `fstodo sync [--source <id>]` | 是 | 同步个人待办；多个可执行来源时必须显式 `--source`，不猜 |
| `fstodo list [--project --type --flow --text --limit --offset]` | 否 | 只读本地缓存；空缓存提示先 sync，不冒充远端状态 |
| `fstodo last-sync` | 否 | 最近一次**成功**同步（失败运行永不占用此位） |
| `fstodo runs [--limit N]` | 否 | 运行台账（含失败与拒绝明细），排查入口 |
| `fstodo sync --auto` | 是 | 同上，但台账记为 automatic（供以后由后端调度时使用） |
| `fstodo types refresh [--source <id>]` | 是 | 发现并保存各空间的可见类型（只读）；某个空间读失败不拖垮整次发现，剩余空间照存，并列出没读到的空间与原因；**一个类型都没发现时不动旧快照**（清空会让下次 `types use` 全部报「不在快照里」，却不留任何痕迹） |
| `fstodo types list [--source <id>]` | 否 | 打印已保存的类型快照与当前生效范围 |
| `fstodo types use [--source <id>] --type-key <k> [--type-key <k>…]` 或 `--clear` | 否 | 记下同步范围（`--source` 缺省用默认来源，来源 id 拼错直接报错；type_key 不在类型快照里当场拒绝，不留下「已记录但永不生效」的范围）；`--clear` 回到「未确认 = 全量」。两者语义相反，**同时给出即拒绝**，不会先清除再悄悄丢掉点名的类型 |
| `fstodo workflow actions <work_item_id> [--project --type]` | 是 | 只读发现动作：打印版本指纹、可执行/不可用及原因 |
| `fstodo workflow run <work_item_id> --action <id> --version <v> [--field k=v] [--yes]` | 视参数 | **真写**：不带 `--yes` 只打印将要提交的请求，一个字节都不发；带 `--yes` 还要配置里 `workflow_enabled = true`，否则直接拒（退出码 6，不发请求、不落台账） |
| `fstodo actions <work_item_id> [--limit N]` | 否 | 该事项的动作流水（含结果不明的那几次） |

`--project` / `--type` 可以省略：本地缓存里有该编号的身份就自动补齐，显式给的永远优先。
缓存里同一编号属于多个空间时**不猜**，直接报冲突要你把身份写全（退出码 12）——这个身份是要拿去写远端的，猜错就是改了别的事项；缓存读不出来说明缓存故障，也不会被当成「没有身份」。

退出码（脚本据此区分「查凭证」还是「查网络」）：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 0 | 成功 | 6 | 配置错误 |
| 3 | 连接失败 | 7 | 凭证错误 |
| 4 | 鉴权失败（含 401 挑战原文回显） | 8 | 数据解析失败 |
| 5 | 工具调用失败 | 9 | 本地缓存错误 |
| 11 | 同步未完成（触到 `max_pages`，数据不完整） | 10 | 能力未实现 |
| 12 | 冲突：动作清单版本已过期，或同一编号在缓存里属于多个空间（需显式 `--project`/`--type`） | 13 | 参数校验未通过 |
| 14 | 权限不足（以服务端声明为准） | 15 | 结果不明（不得据此重试写） |
| 16 | 预留：动作结论 `failed`（当前执行路径不产出——写请求一旦发出就只有 0 或 17） | 17 | 动作结果不确定（先去飞书核对，不要直接重试） |

```powershell
#  - CLI 行为：check/sync 无凭证时退出码 7（已冒烟验证）；CLI 用例与真实 sync_personal_todos 仅差一层 secret=None 包装
```

## 5. 真实读取（需要一次性人工操作）

```powershell
$env:FSTODO_MCP_TOKEN = "<MCP token>"
fstodo check          # 期望：打印服务端名称/版本/协议/能力；401 时退出码 4 并回显 WWW-Authenticate
fstodo sync           # 期望：页数、收到/落库/拒绝条数、结束原因
fstodo list           # 离线核对落库结果
fstodo last-sync; fstodo runs
```

实测记录：伪造 token 时 `initialize` 即失败（`AuthRequired + WWW-Authenticate`，退出码 4）。
**真实 token 已完成验证（2026-10-19）**：建连 `Meego MCP Server 1.0.0`；`sync` 收到 4/落库 4/拒绝 0
（`total_reached`），二次同步幂等（updated 4 / inserted 0）。真实 `content` 为「JSON 数据块 + `log_id:`
诊断块」双文本块、无 `structuredContent`——首轮因此报 Parse 错误（台账 #1/#2 failed），页形状候选适配后通过。

## 6. 流程动作与类型发现的**只读侧**实测（2026-10-19）

> 公开整理说明：本节的事项、节点模板、字段与流转标识已替换为示例占位值；数字 `10001` / `10002` 仅演示响应类型，实测行为与判断结论保持原记录。

凭据是本机 DPAPI 里那份，以下都是真实调用结果，不是样本推断：

| 对象 | 流程 | 实测事实 |
|---|---|---|
| `STORY_EXAMPLE_ID`（story） | 节点流 | `get_node_detail` 返回 `{list, pagination}` 且 `page_size=100` 被忽略：21 个节点分 2 页取完；进行中节点 `state_example`（联调与自测）未完成必填 `schedule`/`point`/`actual_work_time` ⇒ 「完成节点」**DISABLED** 并列出这三个字段名；10 个已完成节点各出一条回滚动作（必填 `rollback_reason`） |
| `ISSUE_EXAMPLE_ID`（issue） | 状态流 | `get_transitable_states` 回 `10001→CLOSED`（缺必填 `field_example` 详情描述 ⇒ DISABLED）与 `10002→REOPENED`（ENABLED）；当前状态「已解决」 |
| 类型发现 | — | `list_workitem_types` 回 `{list:[{api_name,name,type_key,is_disable,enable_model_resource_lib}]}`，本机可见 13 个类型；`is_disable` 恒为 `2`，语义未验证 ⇒ 不参与过滤 |

顺带钉死的接口事实（写请求参数只能来自这些）：

- `transition_node.node_id` 用 `basic.node_key`（如 `state_example`）；传 `node_uuid`（`node_state_11_STORY_EXAMPLE_ID`）报 `NodeNotFound`；
- `get_transitable_states` 的 `transition_id` 响应是**数字**（`10001`），工具声明是 string ⇒ 按声明转字符串，动作 id 用不带引号的文本；
- 节点流的未完成必填是顶层 `node_fields[].field_key`（无 `field_name`、无 `finished`），状态流是 `form_items[].key`；
- `transition_node` / `transition_state` 都没有携带字段值的参数 ⇒ 缺必填只能禁用动作，不能「顺手填上」；
- `list_todo` 对状态流给的 `state_info` 两个键为空串，对节点流给的 `node_state_key` 其实是 node_uuid ⇒ 缓存里没有可用的状态 key。

`workflow_enabled` 默认 true；显式设为 false 时，桌面端只显示接入状态，且两个流程 IPC 直接拒绝。
`fstodo workflow actions`（不带 `--yes`）不写任何数据，可随时复跑。
**真写由使用者本人执行**，步骤与判定见 [写侧验收手册](写侧验收手册.md)。
