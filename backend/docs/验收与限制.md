| R6 | 节点流/状态流 `both` 共存的语义未确认 | 不合并展示 | `flow_kind="both"` 原样保留两组字段，等真实样本 |
| R7 | 旧版未记录完整来源归属 | 升级后的历史事项需各启用来源分别核对 | 2026-10-20 已增加按来源清单校正；完整成功后移除本来源缺席事项，多来源仍包含的事项保留；旧缓存需所有启用来源完整同步后才能全部校正，不调用远端删除 |
| R8 | 会话复用：`sync` 期间出错才重建会话 | 服务端主动失效时首请求可能失败一次 | 失效后下次调用自动新建会话；`check` 永远新建会话验证「当下」 |
| R9 | 响应若真给空串 `project_key`（与字段缺失同键），复合主键碰撞、flags 后写覆盖 | 两条不同来源的记录互相覆盖 | 理论碰撞，真实响应未观测到空串身份段；出现时按报错样本定义区分规则（用户定案：维持现状） |
| R10 | `LooseStr` 使数字 `2002` 与字符串 `"2002"` 落同一主键 | 同上，且是更可能的碰撞路径 | 同上：等真实样本证明是否存在两种写法并存（用户定案：维持现状） |
| R11 | 部分条目可能无法解析 | 不完整结果不能替换当前清单 | 2026-10-20 随同步修复调整为 `Failed`、`complete=false`，保留已取得数据和原有归属，拒绝原因继续写入台账 |
| R12 | `doctor` 无凭证时退出码为 0 | 脚本无法靠退出码区分「凭证缺失」 | doctor 输出如实打印凭证未就绪；需要硬校验用 `check`（退出码 7）（用户定案：维持现状） |
| R13 | 多文本块时按「页形状」取舍，若服务端把**含空 `list` 的对象块**排在数据块前，会静默得到空页并记成功 | 真实数据被吞成「无待办」 | 已用页形状约束（对象须含 `list`）挡掉元数据块抢位（有测试）；空 `list` 块在前属残余风险，真实响应未观测到该形状，出现时按样本再收紧 |
| R14 | 流程动作的**写侧尚未验收**：实现侧只发过读请求 | 写路径的真实行为（尤其 `unknown` 那一支）没有真实样本 | 配置闸门 `workflow_enabled` 默认 true，**CLI 的 `--yes` 与桌面 IPC 都受它约束**（显式关闭时就发不出写请求，退出码 6）；写之前先落 `pending`，回读变了才 `verified`；**永不自动重放写**；验收用例交给使用者本人（[写侧验收手册](写侧验收手册.md)） |
| R15 | 字段更新和流程推进使用独立接口，不具有跨接口事务性 | 字段可能已保存，但节点/状态尚未流转 | 支持的字段在本端填写；确认后先更新字段并回读，再检查必填和流程条件，最后推进；结果不明时保留草稿和提交标记，不自动重放；不支持的字段仍明确阻断 |
| R16 | 状态流单选依赖远端完整选项配置，其他复杂字段尚未全部支持 | 无法识别的必填项不能在本端提交 | 从 `list_workitem_field_config.option` 获取单选名称与 ID，提交 ID 并回读核验；缺选项、重复 ID 或未知必填类型会阻断；不提供动态新增选项 |
| R17 | 空间清单只能枚举**缓存里已出现过的 `project_key`**；类型范围在本地筛 | 全新空间要先同步到事项才能发现类型；范围不减少远端流量 | `types refresh` 的输出与文档都写明来源限制；`items_out_of_scope` 与 `items_rejected` 分开计数 |
| R18 | `ActionOutcome::Failed` 目前不由 `execute` 产出 | 界面/CLI 的 `failed` 分支走不到（退出码 16 为预留） | 枚举与 CLI 常量注释都写明理由：写请求一旦发出，诚实的结论只有 `verified` 与 `unknown`；变体留给台账历史/人工行 |
| R19 | schema v3 首版把 `updated_at` / `created_at` / `finished_at` 声明成 `TEXT`（DDL 已改回 `INTEGER`） | 已经按旧 DDL 建过库的机器，列类型与代码预期不一致 | 读侧统一 `CAST(... AS INTEGER)` 并容忍两种存法，旧行照样读得出；不做事后 ALTER，避免动用户数据 |
| R20 | 节点**回滚**分支不调 `get_transition_required`，所以 `disabled_reason` 恒为空 | 若服务端对回滚另有本端填不了的必填项，只能在写之后落入 `unknown` | 回滚只带工具自己声明的 `rollback_reason`（元数据里「仅回滚时」）；真出现这种必填，写侧验收会以 `unknown` + 服务端原文暴露出来，届时再收紧（待使用者定夺是否预先禁用） |
| R21 | `state_lookup_args` 在缓存没有 `node_state_key` 时，用 `work_item_id` 顶替 `get_transitable_states` 要求的 `node_id` | 该次读会失败，动作清单读不出来 | 只发生在只读探路，这个值**永不**进入写参数（`transition_*` 用的是 `basic.node_key` / `transition_id`）；读失败如实报错，不编造动作（待使用者定夺是否改为直接拒绝） |
| R22 | CLI 曾不检查 `workflow_enabled`（历史问题，已修复） | 手滑命令行曾可写 | CLI 现与桌面端共用配置开关，显式关闭时拒绝写请求 |
