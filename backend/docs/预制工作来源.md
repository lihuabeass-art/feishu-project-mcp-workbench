# 内置与自定义工作来源

桌面“工作来源”包含同级的“已添加的工作来源”和“工作类型”两个设置区域。前者管理来源的添加、启停、编辑与移除，选中来源卡片后，后者管理该来源的类型范围以及全局显示别名。

“添加内置来源”和“添加自定义来源”是两个独立入口。内置来源从目录选择，名称与查询规则固定；“我的待办”等不需要空间的内置来源只能添加一次，“我参与的需求”和“我参与的缺陷”可按不同空间多次添加，同一空间不重复添加同一内置来源。每份来源使用独立稳定 ID，可分别同步、启停和移除，清单的来源选择附带空间名称。自定义来源由用户填写查询方式、空间、类型、视图或关联条件，添加后可以继续编辑及改名。内置来源不提供编辑入口；需要空间的来源在添加时绑定空间，旧配置中未绑定的需求来源仍可通过“设置空间”完成绑定，绑定后固定。要换空间或规则，可移除后重新添加，或创建自定义来源。

0.3.0 起，新用户首次使用时只默认加入可直接同步的“我的待办”。“我参与的需求”和“我参与的缺陷”等来源均由用户按需添加，需要空间的来源须明确选择或填写实际飞书空间后再保存，不默认选择第一个空间。已有配置保持原来的来源列表，显式移除全部来源后不会恢复默认来源。

来源卡片优先显示本机事项或已发现类型中的空间名称，悬停可查看空间标识；尚无名称时回退标识。添加来源复用现有自定义下拉组件，以名称和标识区分空间，同时支持手动填写未同步过的空间标识；候选不是远端完整空间清单。首次使用可先同步“我的待办”获取空间名称。

| 内置来源 | 飞书查询规则 | 用途 |
| --- | --- | --- |
| 我的待办 | `list_todo`: `todo` + `in_progress` | 当下分配给我的工作 |
| 逾期待办 | `list_todo`: `overdue` + `all` | 飞书判定的本人逾期工作 |
| 本周待办 | `list_todo`: `this_week` + `all` | 本周安排，使用飞书本周口径 |
| 尚未开始的待办 | `list_todo`: `todo` + `not_started` | 提前准备下一阶段 |
| 我参与的需求 | `story` + `array_contains(all_participate_persons(), current_login_user())` | 补充个人待办之外的需求 |
| 我参与的缺陷 | `issue` + 同上 | 持续跟进自己参与的问题 |

“当前参与人包含我”“指定人员字段或角色包含我”“飞书已保存视图”等可变配置在自定义来源中设置。人员字段、角色必须先发现后选择，默认任一条件满足，可用开关改为全部满足。普通视图需在飞书保存筛选变更，并填写真实空间和视图 ID。全景视图尚不支持。类型查询可能包含已完成事项，“当前参与”不等同于未完成；不猜测各空间的完成状态、优先级或排期字段。

所有已添加来源都可以启停和移除；移除需要在卡片内确认，仅删除本地来源配置，保留本地已缓存的事项，不修改飞书数据。自定义来源改名只改变 `display_name`，稳定 ID 不变，因此缓存归属、类型范围和同步策略仍关联原来源。

## 数据依据与边界

2026-10-21 对正式 SQLite 缓存执行只读聚合：清单有 17 条需求、3 条缺陷；需求详情中 8 条未完成、9 条已完成。最近成功同步的“个人待办”收到 5 条，“我参与的需求”收到 17 条。详情表还有 7 份缺陷快照，其中部分不在当前清单，不能当成当前清单数量。来源条数有重叠，不能相加当作独立事项数。

2026-10-20 独立验收记录还显示：缺陷全部参与来源 55 条、需求角色来源 13 条、普通视图 10 条，见[工作来源与详情补全](工作来源与详情补全.md)。这些历史样本用于判断覆盖价值，不代表今天的远端实时数量，也不能用于计算精确新增覆盖率。

推荐先加入“我参与的需求”和“我参与的缺陷”补全覆盖，再用“当前我参与的工作”或职责模板聚焦；逾期、本周用于时间安排。最新一次完整成功的全量同步会移除未返回事项的来源归属，没有任何来源的清单项也会移除；旧详情快照仍可能留存。界面结果以最近同步为准，失败或未完成的扫描不会清空旧归属。

默认来源继续使用稳定 ID `personal-todo` 和 `related-story`，内置身份写入 `builtin_key`。从目录新增的来源使用 `builtin-<key>` 标识。旧配置仅在固定 ID 与对应内置规则完全匹配、且没有自定义显示名时识别为内置；用户的新建自定义来源不会因为使用相同 ID 而被锁定。自定义来源新建时避免同名，后续改名保持 ID 不变。
