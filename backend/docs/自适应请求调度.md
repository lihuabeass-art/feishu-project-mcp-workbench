# 自适应请求调度

- 项目既有调查记录指向的[飞书项目 API 文档索引](https://s.apifox.cn/apidoc/docs-site/2823507/llms.txt)列出了 OpenAPI；其中[工作项详情接口](https://s.apifox.cn/apidoc/docs-site/2823507/api-86296745.md)没有提供可用于 MCP 的频率限制说明。
- 普通飞书开放平台、云文档、机器人与飞书项目 MCP 是不同接口，不能将其他接口的额度当成这里的官方配额。现有 4 并发的单组耗时样本也不能证明最佳并发或服务端上限。

因此采用客户端反馈控制，不宣称已确认飞书额度，不对公司项目发起探测上限的压力测试。

## 统一调度

同一端点与凭证摘要的所有 MCP 客户端共享总窗口和限流冷却，内部区分前台交互、来源检查、后台详情三类队列。前台包括事项详情、流程发现、提交前检查和写后核验；SourceReader 将来源清单与人员字段校验标为检查，将批量详情及其续页标为后台。同一工具也可能有不同用途，所以按调用上下文分配类别，不按工具名猜测。

每类内部 FIFO，类间按“前台、检查、前台、后台”循环选择有待处理且能发送的类别，空类别跳过。总窗口至少为 2 时留出一个前台位置，至少为 3 时再留出一个检查位置，后台不能占用这些位置；窗口为 1 时三类仍按轮次共同使用唯一位置，不抢占已经发出的请求。这些是内部响应与公平策略，用户无需配置，不代表飞书分配了独立额度。

取消排队立即释放排队位置；已发请求在调用方取消后仍占用名额，直到响应完成或有界超时清理结束。来源分页和单项详情续页仍按远端协议顺序进行，跨来源的同项详情合并保持不变。

启动总窗口为 8；有待处理需求且成功完成一个窗口后，最多每秒增加 1 个并行名额，最高 64。所有类别共同遵守最小 10 毫秒发出间隔；后台详情额外根据请求耗时平滑值与当前窗口分散发送，短前台请求和来源检查不继承慢详情的发送间隔。64、10 毫秒和每个 Reader 的 128 个待处理任务窗口是客户端资源保护边界，不是官方推荐数值或已测得的服务端容量；实际使用量随任务需求与反馈变化，不会固定跑满上限。

HTTP 429 保留 Retry-After（秒数或 HTTP 日期）；JSON-RPC 错误和 isError 工具响应也识别明确的频控错误，支持结构化 retry_after 秒数。整个共享队列至少等待服务端指定时间，无等待信息时从 1 秒开始指数退避，最高 30 秒。窗口减半，最低为 1；同一旧窗口中迟到的成功响应不能抵消降速。连接失败或超时也缩小窗口；权限或业务校验错误不据此降速。

只有已列明的读取工具在明确限流后自动重试，最多额外两次，初始化限流同样经过共享冷却。HTTP 429 保留共享会话，不中断其他在途调用。SDK 普通 POST 保护上限与调度器的 64 对齐，并显式关闭过期会话自动恢复重放；写工具和未知工具均不重发，继续由业务层的幂等台账和写后核验决定结果。

## 系统超时与配置

握手初始上限 30 秒。工具调用初始上限 30 秒，随后按工具分别维护平均耗时与偏差，采用平均值加四倍偏差，在 10～120 秒范围内调整；超时后放宽下一次等待。一次工具操作的排队、握手、退避与尝试共用 120 秒截止时间，清理失效会话额外最多等待 2 秒。服务端要求的等待长于本次操作剩余时间时，本次有界失败，但共享冷却时间仍保留。

配置文件、桌面设置接口和页面删除来源检查并发、详情并发和请求超时字段。开发阶段不兼容旧字段，严格配置解析将其作为未知键拒绝；没有迁移或忽略逻辑。图片 HTTP 下载继续使用内部 30 秒超时，不再依赖连接配置。

同步台账的请求计数、耗时和并发峰值统计逻辑调用，包含排队与内部退避；本地工具性能日志逐次记录实际尝试。两者口径不同，不用台账峰值推断网络在途峰值或官方限额。

独立存活的握手与工具请求任务继承发起流程的诊断上下文，继续累计实际尝试次数和握手数，并使用同一个请求编号关联逐次日志与流程汇总；没有流程上下文的请求不关联其他流程编号。

## 保留流程读取性能

`ec3da6e` 引入的长驻运行时和会话、详情合并、字段配置缓存、流程模型路由及并发必填项查询继续保留。混合负载回归使用真实 SourceReader、Remote、流程发现、rmcp 和本地 HTTP：让 40 个后台详情形成积压并保持已发详情不完成，此时详情面板、两次流程发现与后续来源检查必须先完成；同时核对只握手一次、前台详情只取一次、字段配置只取一次、节点流不探测状态流，并在释放后台后核对全部详情和原始顺序。

会话生命周期锁只保护建立、替换和取出 Peer 快照，性能日志在释放锁后写入。排队后的发送核对使用每代会话的有效标记，替换、关闭或作废时在锁内标记旧代失效；普通锁争用不会使有效请求丢弃名额重新排队。独立回归保持生命周期锁被占用，验证已取得有效 Peer 的请求仍能发送，并继续验证真正代次替换时的重新取会话行为。

虚拟时钟回归覆盖窗口为 1 时三类都能推进、同类顺序、排队取消、三类共同冷却、短交互不继承慢详情节奏，以及后台保留自适应扩容能力。该验证证明调度隔离与请求复用，不将本地样本耗时当成飞书线上速度保证。
