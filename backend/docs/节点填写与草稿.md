# 流转填写、本机草稿与二次确认

工作台沿用飞书项目的节点、状态、权限、字段配置和必填校验。工作台读取节点表单或目标状态缺失的必填字段并提供填写入口，不复制一套独立的工作流引擎。飞书继续决定流程是否允许推进。

## 用户交互

节点动作清单先展示当前进行中节点的完成动作（包括需要去飞书处理的动作），其次是独立进度／日期同步，最后是历史节点回滚；每组保留远端业务顺序，不按节点名称或中文标签排序。状态流保留已有动作排序规则。排序只影响展示，不改变执行参数、必填判断或快照版本。

1. 点击节点完成、回滚、状态流转或独立进度／日期同步动作时，直接使用已加载的动作和字段快照，不额外发起云端读取或等待检查完成。可本机处理的动作立即进入表单并恢复已有草稿及原编辑基线；云端变化继续由后续检查和提交前核对处理。`requires_feishu=true` 时直接打开对应飞书事项，由用户在飞书填写并直接完成本次流程，无须返回本软件再次推进。工作台不创建或恢复该动作草稿，也不发送字段更新或流程推进请求。无法取得可靠事项链接时显示原因，不回退为本机填写。以下草稿与确认步骤适用于本机动作。
   工作项字段从最新事项详情取值；估分、实际工时与排期按对应负责人取值，无负责人归属时读取节点总排期。个人排期行即使值为空也作为归属依据；必填接口省略负责人或字段退出未完成清单时，已配置字段保持相同负责人身份，不能切换成节点总排期或复制总值。日期转换为北京时间日期，进度转换为百分比，数值 0 同样带入。普通草稿中非空内容优先，空白字段用飞书当前值补齐；提交结果待核实的草稿保留原快照及阻止重复提交的标记。
2. 每次修改立即写入 localStorage，提示“草稿已自动保存在本机，尚未提交飞书”。草稿按空间、工作项类型、事项编号、动作 ID 隔离；关闭表单或应用后可恢复。同一 Windows 用户的应用本机存储范围内保留，不跨设备同步。
   节点进度提供 0～100% 拖动条和可编辑数字，两者同步；拖动按 1% 调整，数字可保留小数。空值显示“未设置”，不会自动当作 0%。估分输入框加减按钮及键盘上下方向键按 0.5 调整，手动输入和已有值仍允许其他小数；当前实测 MCP 字段配置只返回 number，没有步长或精度配置，因此这是本端指定的步长。实际工时在本地填写非负数，允许零和小数，按对应负责人或节点总排期提交。
3. 点击“提交”直接使用当前编辑快照完成本地必填与选项校验、保存草稿并进入二次确认，不额外读取云端动作或等待云端检查；已经在途的后台读取不得覆盖核对内容。最终确认提交时后端重新校验原快照版本与动作可用性，云端冲突则返回可编辑草稿并保留本机输入。窗口重新聚焦或事项更新的后台检查继续用原草稿基线核对：仅云端修改的字段沿用最新值，双方改成相同值时不算冲突；云端空值按未填写处理，不额外拦截或显示清空提示。
4. 默认进入核对页，列出事项、动作及本次字段快照，提醒节点推进与提交后的修改限制。用户可返回修改，勾选已核对并点击确认后才发起正式请求。设置中的“关闭流程操作二次确认”默认关闭；开启时必须先阅读“关闭前，请三思”提示，勾选知悉风险并明确确认，才在本机保存偏好。启用后，节点完成、回滚、状态流转以及独立进度／日期同步在点击对应的提交按钮并通过本地校验后直接发起正式请求，由后端执行云端检查；再次关闭开关立即恢复核对页。新建表单始终保留二次确认。
5. 飞书回读确认生效后清理当前表单的草稿；发送前的明确拒绝保留可编辑草稿；云端版本冲突时提供“重新读取云端，保留草稿”，成功读取并保存最新基线后才允许再次提交，读取失败继续保留输入和重读入口，不自动重发。冲突标记随原草稿保存，关闭或切换事项后重开仍须重读；沿用已有草稿存储键，并兼容未带该标记的旧草稿。发送后结果不明时保留原草稿和提交标记，阻止直接重复提交；点击“重新读取云端，保留草稿”后，只有读取和本机保存都成功才解除本机标记，在原表单核对最新云端值与保留的填写内容，再按当前流程确认偏好主动发起新请求。读取成功本身不表示上次操作已核验成功，读取或草稿保存失败时继续保留原标记。
6. 旧版误归为节点总排期的本机修改，按字段身份中的排期属性匹配当前表单；只有唯一对应的个人字段且没有不同的本机修改时，才恢复进该输入框，不在页面顶部重复显示草稿文本。个人字段的当前云端值继续参与冲突核对，不将节点总值作为个人历史基线；多负责人或已有不同本机填写时由用户明确选择目标并填入。未改过的汇总值不迁移，待核实原提交快照在重新读取前不改写。
7. 仍不能对应的内容在编辑页末尾收拢保留，二次确认完整展示“本次不提交”，不阻止当前操作。实际请求只含当前表单接受的差异字段；本次操作核验成功后，这些未提交内容仍保留在本机。读取发现原动作缺失时自动再读取一次；仍不可用时返回最新动作列表，保留原动作草稿，不自动选择或重放。此后窗口重新聚焦或事项更新时再次读取动作列表。

草稿保存失败时明确提示未保存；无法记录本次提交标记时不会发送正式请求。远端已核验的结果不会因为本机清理草稿失败而被改报为提交失败。

提交等待期间可返回动作列表继续处理其他节点或事项；仅正在提交的同一动作禁用防重，其他动作的编辑、核对和提交保持可用。在途状态覆盖关闭并重开详情、事项切换和布局切换，当前请求结束前不能通过恢复操作解除其保护。每次提交的结果提示和本机草稿独立保留，迟到结果不能关闭或覆盖另一动作正在填写的表单，只清理匹配原 request_id 的草稿提交标记。所有在途流程结束前继续禁止切换连接、凭证或安装更新。

关闭二次确认仅省略核对页，不跳过必填与选项校验、后台已发现的云端冲突展示、本机提交标记、后端版本校验或写后远端回读。写入仍只提交本次操作允许的差异字段；结果不确定时保留草稿与待核实标记，不能直接重发。偏好存储键独立于应用版本，读不到明确的开启值时保留二次确认。

## 字段与接口归属

| 表单内容 | 读取依据 | 正式提交 |
| --- | --- | --- |
| 估分 | `point` 与 `not_finished_owner` | `update_node.schedules[].points` 或节点总排期 |
| 实际工时 | `actual_work_time` 与 `not_finished_owner` | `update_node.schedules[].actual_work_time` 或 `node_schedule.actual_work_time`，保留原字段身份以恢复旧草稿 |
| 排期 | `schedule` 与负责人 | `estimate_start_date` / `estimate_end_date`，北京时间零点毫秒时间戳 |
| 进度 | 节点 `node_progress` | 界面 0～100%，提交为字符串形式的 0～1 数值 |
| 设计文档 | 节点表单及工作项字段配置 | `update_field` 的工作项字段；按真实 field key 定位 |
| 其他基础字段 | 节点/工作项字段配置中的类型、名称和选项 | 根据字段归属选择 `update_node.fields` / `update_field` |
| 人员、关联事项与多选 | 字段配置、当前值及人员／配置范围内的事项查询 | 选择名称、按 ID 编码；关联多选发送数字 ID 数组的 JSON 字符串 |
| 工作项角色 | 表单 role 身份、角色配置及 `role_members` | `update_field.role_operate` 按成员差异 add/remove，不删除角色定义 |
| 富文本图文 | `multi-text` 字符串及所属真实事项字段 | 图文编辑后仅发送正文差异；新图片先上传并保留 file_token，字段写入后核对正文和图片 |
| 普通分负责人复合字段 | `multi_user_compound_field`、递归子字段配置和负责人映射 | 按负责人发送 `operation_type=1` 的子字段增量更新；不包括系统负责人完成信息 |
| 负责人完成结论与意见 | `owners_finished_info` 及其系统子字段 | 由对应负责人在飞书页面填写；仍缺必填时阻断完成动作 |

例如，当前空间的“前端设计文档”是工作项字段 `field_5dbdcc`，不是节点字段。代码以远端 key 和配置归属为准，不把该 key 写死，也不依据中文名称猜接口。

负责人后缀按节点负责人、负责人排期及必填项中的负责人标识合并去重后决定：只有一位负责人时省略，多位负责人时保留区分。这只影响字段标题，提交仍使用原始负责人标识，不依赖项目或自定义字段名称。

字段更新的 `field_value` 按 MCP 元数据要求使用字符串：文本直接传字符串，数值先序列化为 JSON 字符串。排期增量更新显式传 `clear_schedule=false`、`is_auto=false`；分负责人填写，未填他人的排期不被复制或清空。已有估分、工时和排期显示可编辑输入框并回显飞书值，包含只在节点汇总区返回的字段；用户修改后按确认页中的值提交，允许覆盖原值，并按相同负责人或节点总值回读核验。飞书仍缺少的字段保留必填校验，已经填写的字段不因退出未完成清单而隐藏。

排期提供“仅同步此日期”，在独立动作中同时填写并核对开始、结束日期，两端必须完整且结束不早于开始。动作仅接受对应节点／负责人的排期日期，保留未改动的云端日期，实际仅写差异，不携带进度、估分、工时、文档或流程推进。云端其他流转必填项不阻断日期同步；即使两端无差异，也必须回读核对两个日期并确认节点仍为进行中。写入回执异常时仍回读，已核验生效则显示成功并仅在动作台账记录回执异常；未能核验时保留草稿和结果不确定，禁止自动重发。

## 页面处理说明、节点必填项与 API 提交阻断

能否推进以当前节点的 `get_transition_required(mode=unfinished)` 结果为依据：接口列出的才是仍未满足的流转必填项，`finished=true` 的条目不参与阻断。字段出现在表单或元数据中、类型不可写，均不能单独作为禁止流转的理由；不可写字段非必填或已经满足时继续核对并允许推进，即使没有字段差异也可以提交节点推进请求，最终仍须远端回读核验。

动作列表和跳转前尚未发起流程推进，此时说明本软件无法通过 API 处理本次动作、需要在飞书页面处理，不能把尚未执行的动作称为“流转失败”。用户可以在飞书填写并直接完成流程；回到工作台刷新或同步仅是查看最新状态的可选操作。

对于结合当前接口与真实拒写记录确认不可写的字段，仅在它仍为未完成必填项时阻断本软件的 API 完成请求。官方文档可能落后或矛盾，不能单凭 §4.3 的名单撤掉已有能力，具体见[字段能力核验记录](MCP字段能力核验.md)。后端对已确认的页面专有字段保留[飞书官方节点操作说明 §4.3](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/sop-transition-node.md)的原始阻断模板，只替换节点名称、真正缺失的字段名称和不可写字段分类；该模板不作为尚未提交时的页面处理说明：

> 节点流转失败。当前节点【节点名称】设置了必须填写【字段名称】（类型：xxx）才能流转。由于该字段类型不支持自动化补充，请您在飞书项目页面手动填写后，再通知我继续流转。

这是官方操作说明提供的提示模板，不是本次 API 已返回的原始错误，也不说明已经发送过流程推进。负责人复合字段缺少“负责人完成结论”时，字段名称使用该子项名称，类型使用官方不可写分类 `owners_finished_info`，不得将未缺失的意见混称为必填；也不得将通用的 `select` 或 `multi_user_compound_field` 误报为不可写类型。对应负责人可直接在飞书页面填写并完成节点，工作台可选刷新同步最新状态；旧版本机填写继续保留，不会被自动重放。真实提交已经发送后，飞书返回的错误与写入结果不确定仍按实际回执和远端回读明确反馈。

`manual_fill_required` 只描述仍缺少且本地无法补充的流转必填项；仅这些缺项使 `requires_feishu=true`，由界面引导到飞书处理。系统只读字段、投票或本端尚未支持的字段类型可选或已满足时，保留本地流程操作，以只读快照完整展示云端值且不写入这些字段。关联事项已有本地选择入口，按名称核对，原始身份和值继续参与操作版本校验；未修改时允许零差异推进。仍缺必填配置、必填选项配置错误或无法确认必填负责人时，继续保留写入阻断并提供飞书入口。界面使用 `requires_feishu` 作为直接跳转依据，不从提示文案猜测；真正动作不可用或权限失败继续使用原有逻辑，独立进度／日期同步与回滚不继承其它流转必填要求。

入口打开对应事项详情页。后端在同一次已读取详情中核对空间 key、工作项类型与事项 ID，使用空间 `simple_name` 和当前连接的已确认飞书项目官方端点，按[官方页面链接规则](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/url-links.md)生成并验证 `/{simple_name}/{work_item_type}/detail/{work_item_id}`。其中路由类型优先使用详情明确返回的 `api_name`；未返回时使用已核实的 `story`／`issue` 固定映射，其他类型读取同一空间的类型列表，使用唯一匹配的 `type_key` 所对应的 `api_name`，不把任意自定义 `type_key` 当作路由。动态路径段按 RFC 3986 编码；字段缺失、身份不一致、端点或网页域名无法确认、路由有歧义时不生成链接，也不把设计文档、附件地址或空间 key 当作替代事项链接。跳转本身不提交字段、不推进流程；用户在飞书可以直接填写并完成流程，无须返回工作台再次推进，查看最新状态时可选刷新同步。

### 流程入口与字段编辑的判定表

仅判断当前动作实际涉及的字段，不用整个空间的字段配置扩大动作范围。未完成必填项以飞书接口为准，不能用“已有值”或字段名称代替必填结果。

| 当前字段情况 | 本地字段表现 | 流程入口 |
| --- | --- | --- |
| 本地支持编辑，仍缺必填 | 展示对应输入控件并校验 | 本地填写后按确认偏好提交 |
| 本地不支持编辑，仍缺必填 | 不开放本地填写 | 点击动作直接去飞书填写并完成流程 |
| 本地不支持编辑，非必填且为空 | 只读显示未填写，不要求补齐 | 允许在本地推进 |
| 本地不支持编辑，非必填或云端已满足 | 只读展示云端值，不发送该字段 | 允许在本地推进 |

流程表单将 `multi-text` 字符串作为图文编辑，图片链接与 file_token 在可视图片后保留；`multi-pure-text` 保持纯多行文本编辑。未知对象／数组形状的富文本保持原始只读快照，不用空编辑框覆盖原内容。图片通过真实事项字段读取和上传，节点富文本无法核对事项字段归属时可以编辑文字，但图片须在飞书查看或修改，不猜字段或直接下载。新图片草稿在稳定的账号、事项、字段上下文保存，检查阶段上传后保存引用；确认前的预览从本机缓存读取新图片，正式字段写入仍在确认后执行。原有可编辑字段身份保持稳定以恢复旧草稿，仍然只读的历史填写继续显示为“本次不提交”。

人员、关联事项与多选在编辑、云端刷新、草稿恢复及二次确认中保留所选名称；实际核验依据 ID 集合。多选的显式清空与未改动区别处理，必填空数组禁止提交。节点整体 `node_finished_conclusion` 与 `node_finished_opinion` 若由配置启用，分别发送单字段 `update_node` 请求；它们不等同于页面专有的系统负责人完成信息。

可本地推进的表单使用“在飞书中修改”提供只读字段的修改入口，字段说明明确“云端只读值”；只有必须补齐的缺项才使用“去飞书填写”。新发现必填缺项后，已打开的本地表单停止编辑和提交，保留草稿并提供飞书入口。

## 后端执行顺序与边界

后端按“同一动作防重 → 同事项写入排队 → 重新发现动作 → 版本及字段校验 → SQLite pending 登记 → 再次核对版本 → 工作项/节点字段更新 → 回读字段与必填项 → 节点推进 → 回读流程结果”执行。动作列表提供独立动作指纹，仅核对该动作涉及的状态、权限、字段及参数；无关节点变化不使当前操作失效，共享字段或当前动作变化仍拒绝旧快照。旧客户端和已有草稿的整份快照指纹继续按原有严格规则校验。相同 request_id 不重放；同一事项存在 pending 时，新请求也不能交错写入。进程异常留下 pending 时，必须先核对远端与动作台账，不能仅靠清除前端草稿标记绕过。

字段调用失败、回读不一致或仍缺必填时，停止发送节点推进请求，返回结果待核实并保留草稿。未读取到字段的有效云端值与读取到不同值分别提示为字段保存待核实，不将其误称为流程已变更；数字零仍是有效值，核验继续严格区分节点总值与对应负责人值。字段更新和节点推进是多个飞书接口，不能保证跨接口事务原子性；字段可能已经更新但节点尚未推进，也不能完全排除其他人在最终检查后同时操作飞书。工作台不会自动重试这些写请求。

节点流和状态流共用字段解释，支持文本、纯多行文本、图文、链接、数字、日期、单选、多选、radio、布尔、人员、关联事项和角色，以及节点排期、估分和实际工时。布尔字段通过现有自定义单选控件显示“是／否”，有效的 `false`、数字 `0` 会正常回显和核对。本轮覆盖两个事项模板全部 21 个节点涉及的字段；模板未出现的附件、树选择等扩展类型不属于本轮支持范围，不据此断言飞书 API 不支持。

## 远端配置驱动的负责人复合字段（2026-10-27）

`multi_user_compound_field` 递归读取 `compound_field_info`，从必填接口只返回的子字段 key 找回唯一父路径；远端提供完整路径时允许不同父字段复用同一个子字段 key。字段身份包含事项／节点范围、每层父字段和负责人，草稿、版本指纹、提交及回读均使用该身份，不依赖中文名称。必填负责人限制保留在相应层级，节点字段只允许当前节点负责人。

普通复合字段的选项由远端配置提供；同一支持类型的新字段、名称调整或选项变化，无需新增业务字段 key 的代码分支。系统的“负责人完成结论”和“负责人完成意见”虽然也挂在 `multi_user_compound_field` 类型的 `owners_finished_info` 下，但不适用普通复合字段的写入能力判断：后端仅保留只读云端快照，不生成写入计划；只有这些字段仍缺必填时，点击动作才直接打开飞书事项，由用户在飞书填写并完成流程；字段可选或已满足时，在本机核对云端只读快照并允许提交流程推进，提交请求不携带只读字段。页面入口说明不使用执行失败语气，正式 API 提交被阻断时仍保留官方提示；工作台刷新同步仅用于可选查看最新状态。只读字段保留独立身份，旧版本机填写继续保留且不会自动重放；后端拒绝提交只读字段。全新交互类型或不同写入协议仍需要增加类型支持，不包含适配包加载机制。

MCP 的复合字段外层 `field_value` 使用 JSON 字符串，内容为 `{"operation_type":1,"group_editor":"负责人标识","sub_field_value":[...]}`。只发送该负责人的本次差异子字段，不替换整个人员映射、不增加或移除负责人。不同负责人分别调用接口；嵌套复合字段按父路径逐层包装增量操作。工作项复合字段使用 `update_field`，节点复合字段使用 `update_node`。

写入后必须从相同范围、完整父路径及同一负责人回读验证，并重新查询剩余必填项，才能继续推进。其他负责人恰好拥有相同值不能通过验证。回读失败、不一致、剩余必填或写入回执异常时停止推进、保留草稿与待核实记录，不自动重发。仅同步进度继续只处理进度。

2026-10-30 重新用真实只读接口核对了节点子字段配置、负责人映射与 MCP 工具元数据。普通多人复合字段的按人增量契约仍然存在，但仅凭该元数据无法证明系统负责人完成信息可写；真实提交已返回 `invalid owners_finished_info value`，[飞书官方节点操作说明](https://github.com/larksuite/meegle-cli/blob/main/skills/meegle/references/sop-transition-node.md)也将其列为仅支持页面填写。本地模拟覆盖发送前阻断、普通复合字段写入被拒绝后保留待核实与不重发；本次排查未对真实事项执行字段写入或流程推进。嵌套增量格式已有本地回归，尚未在真实嵌套字段上写入验证。

## 状态流必填填写（2026-10-20）

状态流动作按 `get_transition_required(mode=unfinished)` 的真实字段 key、`confirm_form` 名称及 `list_workitem_field_config` 配置建立必填表单，支持文本、多行文本、链接、数字、日期和单选。缺少支持的必填字段时动作可选，界面提示“需填写”；未知类型、非工作项字段及不完整的单选选项仍明确阻断。

单选从字段配置的 `option[].option_id/option_name` 获取，不硬编码名称或选项。界面展示名称，确认页同样展示名称，正式 `update_field` 使用选项 ID；回读支持单个 ID 和 `{label,value}`，以 ID 核对。日期使用北京时间零点毫秒时间戳。输入自动保存本机草稿，检查与确认前不写飞书。

状态流先调用 `update_field`，回读字段和目标状态的剩余必填项，再确认当前状态仍与原快照一致、原 transition_id 和目标状态仍可用，最后调用 `transition_state`。这里不调用节点字段更新或查找目标节点；当前状态、字段配置和选项变化进入版本指纹。

字段保存后流转失败或回读不明时，提示字段已保存以及流转结果待核实；字段写入或字段核验不明确时不发送流转请求。草稿和提交标记保留，不自动重放。两个接口不具备跨接口事务性。

本轮只读实测确认了缺陷“解决结果”的单选配置、已填写实例的 `{label,value}` 回读形状以及 MCP 元数据的选项 ID 提交格式，没有执行真实字段更新或状态流转。

流程能力仍受 `workflow_enabled` 控制，默认开启；本轮仅做真实只读接口核对与离线测试，未执行真实字段写入或节点推进。可在 `%APPDATA%\\FSTODO\\config.toml` 显式设为 `false` 关闭。
