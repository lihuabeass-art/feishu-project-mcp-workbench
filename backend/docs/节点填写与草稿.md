# 流转填写、本机草稿与二次确认

工作台沿用飞书项目的节点、状态、权限、字段配置和必填校验。工作台读取节点表单或目标状态缺失的必填字段并提供填写入口，不复制一套独立的工作流引擎。飞书继续决定流程是否允许推进。

## 用户交互

1. 选择节点动作后读取远端字段和初始值，并恢复该动作已有的本机草稿。
   工作项字段从最新事项详情取值；估分、实际工时与排期按对应负责人取值，无负责人归属时读取节点总排期。个人排期行即使值为空也作为归属依据；必填接口省略负责人或字段退出未完成清单时，已配置字段保持相同负责人身份，不能切换成节点总排期或复制总值。日期转换为北京时间日期，进度转换为百分比，数值 0 同样带入。普通草稿中非空内容优先，空白字段用飞书当前值补齐；提交结果待核实的草稿保留原快照及阻止重复提交的标记。
2. 每次修改立即写入 localStorage，提示“草稿已自动保存在本机，尚未提交飞书”。草稿按空间、工作项类型、事项编号、动作 ID 隔离；关闭表单或应用后可恢复。同一 Windows 用户的应用本机存储范围内保留，不跨设备同步。
   节点进度提供 0～100% 拖动条和可编辑数字，两者同步；拖动按 1% 调整，数字可保留小数。空值显示“未设置”，不会自动当作 0%。估分输入框加减按钮及键盘上下方向键按 0.5 调整，手动输入和已有值仍允许其他小数；当前实测 MCP 字段配置只返回 number，没有步长或精度配置，因此这是本端指定的步长。实际工时及其他普通数字继续允许小数。
3. 点击“提交”先重新读取云端动作与当前值，用原草稿基线逐字段核对并保留本机修改。新发现的值冲突先展示在原表单，核对后可继续进入二次确认；最终提交时后端仍重新校验版本与动作可用性。
4. 核对页列出事项、动作及本次字段快照，提醒节点推进与提交后的修改限制。用户可返回修改，必须勾选已核对并点击“确认提交并执行”才发起正式请求。
5. 飞书回读确认生效后清理当前表单的草稿；发送前的明确拒绝保留可编辑草稿。发送后结果不明时保留原草稿和提交标记，阻止直接重复提交；点击“重新读取云端，保留草稿”后，只有读取和本机保存都成功才解除本机标记，在原表单核对最新云端值与保留的填写内容，再经二次确认发起新请求。读取成功本身不表示上次操作已核验成功，读取或草稿保存失败时继续保留原标记。
6. 旧版误归为节点总排期的本机修改，按字段身份中的排期属性匹配当前表单；只有唯一对应的个人字段且没有不同的本机修改时，才恢复进该输入框，不在页面顶部重复显示草稿文本。个人字段的当前云端值继续参与冲突核对，不将节点总值作为个人历史基线；多负责人或已有不同本机填写时由用户明确选择目标并填入。未改过的汇总值不迁移，待核实原提交快照在重新读取前不改写。
7. 仍不能对应的内容在编辑页末尾收拢保留，二次确认完整展示“本次不提交”，不阻止当前操作。实际请求只含当前表单接受的差异字段；本次操作核验成功后，这些未提交内容仍保留在本机。原动作已不可用时返回最新动作列表，保留原动作草稿，不自动选择或重放。

草稿保存失败时明确提示未保存；无法记录本次提交标记时不会发送正式请求。远端已核验的结果不会因为本机清理草稿失败而被改报为提交失败。

## 字段与接口归属

| 表单内容 | 读取依据 | 正式提交 |
| --- | --- | --- |
| 估分 | `point` 与 `not_finished_owner` | `update_node.schedules[].points` 或节点总排期 |
| 实际工时 | `actual_work_time` 与 `not_finished_owner` | `update_node.schedules[].actual_work_time` 或节点总排期 |
| 排期 | `schedule` 与负责人 | `estimate_start_date` / `estimate_end_date`，北京时间零点毫秒时间戳 |
| 进度 | 节点 `node_progress` | 界面 0～100%，提交为字符串形式的 0～1 数值 |
| 设计文档 | 节点表单及工作项字段配置 | `update_field` 的工作项字段；按真实 field key 定位 |
| 其他基础字段 | 节点/工作项字段配置中的类型、名称和选项 | 根据字段归属选择 `update_node.fields` / `update_field` |
| 分负责人复合字段 | `multi_user_compound_field`、递归子字段配置和负责人映射 | 按负责人发送 `operation_type=1` 的子字段增量更新 |

例如，当前空间的“前端设计文档”是工作项字段 `field_5dbdcc`，不是节点字段。代码以远端 key 和配置归属为准，不把该 key 写死，也不依据中文名称猜接口。

负责人后缀按节点负责人、负责人排期及必填项中的负责人标识合并去重后决定：只有一位负责人时省略，多位负责人时保留区分。这只影响字段标题，提交仍使用原始负责人标识，不依赖项目或自定义字段名称。

字段更新的 `field_value` 按 MCP 元数据要求使用字符串：文本直接传字符串，数值先序列化为 JSON 字符串。排期增量更新显式传 `clear_schedule=false`、`is_auto=false`；分负责人填写，未填他人的排期不被复制或清空。已有估分、工时、排期仍显示可编辑输入框并回显飞书值，包含只在节点汇总区返回的字段；用户修改后按确认页中的值提交，允许覆盖原值。飞书仍缺少的字段保留必填校验，已经填写的字段不因退出未完成清单而隐藏。

排期提供“仅同步此日期”，在独立动作中同时填写并核对开始、结束日期，两端必须完整且结束不早于开始。动作仅接受对应节点／负责人的排期日期，保留未改动的云端日期，实际仅写差异，不携带进度、估分、工时、文档或流程推进。云端其他流转必填项不阻断日期同步；即使两端无差异，也必须回读核对两个日期并确认节点仍为进行中。写入回执异常时仍回读，已核验生效则显示成功并仅在动作台账记录回执异常；未能核验时保留草稿和结果不确定，禁止自动重发。

## 后端执行顺序与边界

后端按“事项互斥 → 重新发现动作 → 版本及字段校验 → SQLite pending 登记 → 再次核对版本 → 工作项/节点字段更新 → 回读字段与必填项 → 节点推进 → 回读流程结果”执行。相同 request_id 不重放；同一事项存在 pending 时，新请求也不能交错写入。进程异常留下 pending 时，必须先核对远端与动作台账，不能仅靠清除前端草稿标记绕过。

字段调用失败、回读不一致或仍缺必填时，停止发送节点推进请求，返回结果待核实并保留草稿。未读取到字段的有效云端值与读取到不同值分别提示为字段保存待核实，不将其误称为流程已变更；数字零仍是有效值，核验继续严格区分节点总值与对应负责人值。字段更新和节点推进是多个飞书接口，不能保证跨接口事务原子性；字段可能已经更新但节点尚未推进，也不能完全排除其他人在最终检查后同时操作飞书。工作台不会自动重试这些写请求。

节点流和状态流共用基础字段解释，支持文本、多行文本、链接、数字、日期、单选、radio 和布尔值，以及节点原有的排期和工时字段。布尔字段通过现有自定义单选控件显示“是／否”，有效的 `false`、数字 `0` 会正常回显和核对。附件、人员选择等未实现类型遇到未满足必填时仍阻断操作。

## 远端配置驱动的负责人复合字段（2026-10-27）

`multi_user_compound_field` 递归读取 `compound_field_info`，从必填接口只返回的子字段 key 找回唯一父路径；远端提供完整路径时允许不同父字段复用同一个子字段 key。字段身份包含事项／节点范围、每层父字段和负责人，草稿、版本指纹、提交及回读均使用该身份，不依赖中文名称。必填负责人限制保留在相应层级，节点字段只允许当前节点负责人。

例如“产品经理验收”的“负责人完成结论”和“负责人完成意见”来自 `owners_finished_info` 的子字段，不再因顶层找不到子字段配置而要求跳到飞书填写。结论选项由远端配置提供。云端每位负责人的已有值回显到现有表单与确认页；同一支持类型的新字段、名称调整或选项变化，无需新增业务字段 key 的代码分支。全新交互类型或不同写入协议仍需要增加类型支持，本轮不包含适配包加载机制。

MCP 的复合字段外层 `field_value` 使用 JSON 字符串，内容为 `{"operation_type":1,"group_editor":"负责人标识","sub_field_value":[...]}`。只发送该负责人的本次差异子字段，不替换整个人员映射、不增加或移除负责人。不同负责人分别调用接口；嵌套复合字段按父路径逐层包装增量操作。工作项复合字段使用 `update_field`，节点复合字段使用 `update_node`。

写入后必须从相同范围、完整父路径及同一负责人回读验证，并重新查询剩余必填项，才能继续推进。其他负责人恰好拥有相同值不能通过验证。回读失败、不一致、剩余必填或写入回执异常时停止推进、保留草稿与待核实记录，不自动重发。仅同步进度继续只处理进度。

本轮通过真实只读接口核对了验收节点的子字段配置、当前负责人映射以及 MCP 的按人增量更新契约；写入与推进链路使用离线模拟验证，未对真实事项执行写入。嵌套增量格式已做本地回归，尚未在真实嵌套字段上写入验证。

## 状态流必填填写（2026-10-20）

状态流动作按 `get_transition_required(mode=unfinished)` 的真实字段 key、`confirm_form` 名称及 `list_workitem_field_config` 配置建立必填表单，支持文本、多行文本、链接、数字、日期和单选。缺少支持的必填字段时动作可选，界面提示“需填写”；未知类型、非工作项字段及不完整的单选选项仍明确阻断。

单选从字段配置的 `option[].option_id/option_name` 获取，不硬编码名称或选项。界面展示名称，确认页同样展示名称，正式 `update_field` 使用选项 ID；回读支持单个 ID 和 `{label,value}`，以 ID 核对。日期使用北京时间零点毫秒时间戳。输入自动保存本机草稿，检查与确认前不写飞书。

状态流先调用 `update_field`，回读字段和目标状态的剩余必填项，再确认当前状态仍与原快照一致、原 transition_id 和目标状态仍可用，最后调用 `transition_state`。这里不调用节点字段更新或查找目标节点；当前状态、字段配置和选项变化进入版本指纹。

字段保存后流转失败或回读不明时，提示字段已保存以及流转结果待核实；字段写入或字段核验不明确时不发送流转请求。草稿和提交标记保留，不自动重放。两个接口不具备跨接口事务性。

本轮只读实测确认了缺陷“解决结果”的单选配置、已填写实例的 `{label,value}` 回读形状以及 MCP 元数据的选项 ID 提交格式，没有执行真实字段更新或状态流转。

流程能力仍受 `workflow_enabled` 控制，默认开启；本轮仅做真实只读接口核对与离线测试，未执行真实字段写入或节点推进。可在 `%APPDATA%\\FSTODO\\config.toml` 显式设为 `false` 关闭。
