# FSTODO 桌面前端

React + TypeScript + Vite 界面，Tauri 2 桌面壳通过 IPC 复用 `../backend` Rust 库，不启动 HTTP 服务。连接页通过密码框提交 token，后端加密保存，页面只接收脱敏摘要。

产品介绍、截图与下载见[项目首页](../README.md)，其余当前说明见[文档索引](../docs/README.md)。[产品定位与演进方向](../docs/design/产品定位与演进方向.md)说明软件根基及尚未实现的多 MCP 演进边界。

## 启动

需要 Node.js 22+、Rust 1.88+、Windows MSVC Build Tools 与 WebView2。依赖锁文件已按 Rust 1.88 解析；`frontend/.cargo/config.toml` 会优先选择兼容版本。

在此目录执行：

```sh
npm ci
npm run tauri dev
```

桌面应用使用与后端 CLI 相同的 `%APPDATA%/FSTODO/config.toml` 和 `%LOCALAPPDATA%/FSTODO/fstodo.db`，配置里的 `db_path` 仍可覆盖。在「连接与配置」中保存 MCP token 后，后端使用 Windows 当前用户的 DPAPI 加密，仅将密文写入 SQLite 独立凭证表；页面只回显来源和长度，保存成功或离开配置页会清空密码框。已保存 token 优先于环境变量和仓库外令牌文件，未保存时仍支持这两种来源。

正常查询共用应用内长驻 MCP 会话，由系统统一调度请求；流程读取合并重复详情请求并缓存字段配置。性能日志保存在 `%LOCALAPPDATA%/FSTODO/logs`，最多保留 7 天、总量最多 10 MiB，启动和运行期间自动清理，详见 [流程读取性能与本地日志](../backend/docs/流程读取性能与本地日志.md)。

「连接与配置」保留 MCP 服务地址和凭证设置。请求并发、限流退避与超时由系统自动管理，详见[自适应请求调度](../backend/docs/自适应请求调度.md)。有效修改停止输入 600 毫秒或离开输入框后自动保存并回读生效，无需保存按钮。应用配置和链接打开方式共用设置页顶部的保存提示，失败时保留草稿并提供重试；无效输入不会落盘。工作来源条件在「工作来源」页面修改。

桌面端自动翻页直到取完所选来源范围的数据和完整详情，永久保留同步运行记录，并默认启用流程操作。旧配置中的页数上限、记录轮转和流程开关不会限制桌面端；实际执行流程仍需核对并确认。原数据库路径和凭证来源继续使用，自动保存不会覆盖它们。CLI 仍支持手工配置技术参数。

Windows 密文与原系统用户绑定，复制数据库到其他用户或电脑后需重新设置 token；加密密钥不随数据库保存。数据库会自动迁移并保留既有事项与同步记录。macOS 使用系统钥匙串保护凭证，安装与签名边界见[macOS 构建与安装](../docs/macos试用版构建.md)。

```sh
npm run dev       # 仅浏览器布局预览，无真实数据和同步能力
npm run build     # TypeScript 检查和前端产物
npm test          # 关键交互回归
cargo check --locked --manifest-path src-tauri/Cargo.toml
npm run build:windows       # 当前版本 tag 的 Windows NSIS 安装包
npm run build:windows:beta  # 兼容命令，版本由当前 tag 决定
npm run build:macos         # 当前版本 tag 的 macOS Universal DMG
```

### 发版版本

发版按[发版流程](../docs/release-process.md)执行，构建使用同一提交的版本 tag，无需手改源码版本。Windows x64 安装包在本机构建，macOS Universal 由 `Build macOS` 工作流构建；完整包自动更新的签名、清单与交付说明见[自动更新文档](../docs/auto-update.md)。文档整理和日常开发不代表已经发版。

侧栏将 `FSTODO v版本号` 与「飞书 MCP 驱动」分行显示；点击版本号可离线查看当前版本的完整更新记录。记录由 tag 间的提交生成，同一 tag 和历史在本机与 CI 生成相同内容，软件内记录与随包 `RELEASE_NOTES.md` 使用同一份构建快照。无 tag 的开发提交显示带提交号的开发版本和开发记录提示。`npm run release:notes -- --version 用户指定版本号` 只预览记录，完整规则见发版流程。

Windows 安装包生成到 `src-tauri/target/release/bundle/nsis/`（自定义 Cargo target 目录时跟随该目录）。安装包会在电脑缺少 WebView2 Runtime 时联网下载引导程序并补装；不内置体积较大的 WebView2 离线运行时。开发仍使用 `npm run tauri dev`，Vite 热更新与原有开发地址保持生效。使用者无需安装 Node.js、Rust 或 SQLite，首次运行会在自己的用户目录中自动创建数据库，飞书凭证需自行配置。安装包应在干净的 Windows 环境验证后分发。

## 已实现

- 「连接与配置 → 窗口与桌面」提供「跟随虚拟桌面」开关，默认开启；关闭后主窗口恢复普通窗口行为。选择立即生效并保存在本机，应用启动时恢复，无需打开设置页。Windows 使用窗口固定（winvd 0.0.49，要求 Windows 11 24H2 26100.2605 及以上）；macOS 使用 Tauri 的所有工作区显示接口，覆盖普通桌面 Space，全屏应用 Space 的表现需在 Mac 上实测。系统调用失败会提示并可重试，保存失败会明确提示仅本次生效。浏览器预览禁用此开关；其他平台暂不支持。此开关不改变窗口置顶。Windows 专用依赖和实现均按目标平台隔离，macOS 分支尚待 Mac 构建及实机验收。

- 详情面板按使用频率分层：概要（当前状态、当前负责人、优先级、创建与更新）和角色人员直接展开；人员、枚举、日期显示为文字，未指派角色与未填写字段各合并为一行；自增数字、流程版本、内部状态 key、完成/冻结标记等飞书内置系统字段收进默认折叠的「更多字段」；空间与类型标识等收进底部「技术信息」。自定义字段（`field_xxxxxx`）始终视为业务内容。
- 业务字段短值以标签对齐的紧凑列表显示，长文、链接与图片独占整行，各组内保持原顺序展示图文，支持 Markdown/HTML 内嵌图片、图片附件及常见结构化图片节点。图片按需加载并本地缓存，点击可缩放、拖动预览；失败可单独重试。真实飞书 PNG 下载及缓存复用已验证，格式与大小边界见 [业务字段图片](../backend/docs/业务字段图片.md)。
- 「连接与配置」提供「链接打开方式」，可选「新窗口」（默认）或「已有浏览器」，选择后自动保存在本机并立即生效。「新窗口」在 Windows 中读取该协议的默认浏览器，对 Chrome、Edge、Firefox 请求新建窗口，适合在当前虚拟桌面查看；「已有浏览器」交给系统默认浏览器处理。窗口所属桌面由浏览器和 Windows 决定，需在目标环境验收。其他默认浏览器、无法解析的协议关联及非 Windows 平台仍按系统默认方式打开，可能复用已有窗口或标签。浏览器预览保留普通网页链接行为。
- 缓存清单，按真实缓存中的类型、空间、流程模型筛选，按标题/编号/空间搜索。
- 完整模式与清单模式共用空间、所属项目、流程类型、节点和状态候选：每类候选按当前搜索、事项类型和其他已生效条件下的实际工作生成，计算时排除自身选择以保留切换与多选能力。空间与项目目录只补充正式名称，不加入没有工作事项的候选；已选条件变成零结果时保留名称供取消，取消后不再作为空候选出现。
- 两种模式共用条件变更规则：调整空间清除项目与流程条件，调整项目清除流程条件，调整流程类型清除节点与状态；搜索和当前事项类型继续保留。
- 使用空间、类型、事项编号组成稳定身份；详情分别展示节点和状态，不猜流程模型。
- 选择启用且可执行的配置来源，或使用“所有已启用来源”依次同步。来源选择控制同步，不过滤历次缓存。
- 手动同步与连接检查在阻塞线程调用后端，不嵌套 Tokio runtime、不冻结页面。失败也回读缓存与台账，未完成不显示成功。
- 凭证就绪时，所有启用且可执行来源每 2 分钟独立自动检查；旧后端仍按所选来源调度。手动和自动同步合并重复请求，自动成功静默；手动成功用悬浮提示展示 5 秒，失败保留单条页面内提示。
- 同步失败后按 4、8 分钟退避，之后持续每 8 分钟重试，各类错误均不会永久停止检查；成功后恢复 2 分钟周期。按来源保存重试计划，兼容旧版已保存的暂停状态；网络恢复、窗口重新获得焦点或页面回到前台时提前重试失败来源，成功来源保持原周期。凭证或配置错误仍需修正才能同步成功；窗口关闭后不调度。
- 「工作来源」的「工作类型」以同一列表管理清单显示、别名与同步选择，不再重复列出类型。名称优先使用本机别名，其次是已发现的飞书类型名，再回退内置名称或原始 key；侧栏、清单筛选与详情使用相同名称。同 key 名称冲突时按来源 id、空间 key、名称排序选取，避免回读顺序改变名称。显示偏好保存在本机；筛选、事项身份和同步始终使用原始类型 key。选择来源后，可发现类型并保存同步范围；恢复全部与明确选空分别处理。相同类型 key 在已发现的各空间一起选择；范围在本地接收数据时筛选，不减少远端请求，也不删除已有缓存。仅缓存、未在所选来源发现的类型仍可调整显示与别名，不参与同步选择。发现范围限于缓存中已出现的空间。「连接与配置」独立管理飞书凭证与连接检查。
- 去掉同步记录页面、已收集工作统计和「栖」品牌字；后端原有同步台账保留作诊断，不在侧栏刷屏。
- 流程动作、必填字段、确认提交与回读核验已接到后端 IPC。桌面端流程能力默认启用，保留提交前确认。CLI 仍受 `workflow_enabled` 和 `--yes` 约束。旧后端不返回 `capabilities` 时保持只读并提示更新。验收步骤见 [写侧验收手册](../backend/docs/写侧验收手册.md)。
- 浅色窗口与响应式详情栏；Windows 11 配置原生 Mica，其他环境由浅色背景保证可读。材质效果需在目标桌面上检查。
- 清单模式：完整模式顶栏右侧按钮把同一窗口切换为紧凑小窗（默认 360×640），只保留「我的工作」清单与详情，数据、来源、同步和主题与完整模式共用。清单筛选从空间开始，项目选项随空间联动；类型、完成情况与流程节点／状态收在「更多条件」。切换空间清除项目及其下层条件，切换项目清除更多条件；当前实现与完整模式共用搜索与筛选，切换模式保留同一组条件，入口默认收起，生效后显示条件数与结果数并可一键清除。自绘标题栏提供刷新、置顶（首次默认开启）、切回完整模式、最小化与关闭，空白处可拖动。标题最多两行，被截断的标题悬停 300ms 或键盘聚焦时原位展开；点击或 Enter 在小窗内打开详情，Esc 返回并恢复滚动位置。显示模式、置顶和两种模式各自的窗口位置与尺寸由桌面端保存在应用配置目录的 `display-mode.json`，启动时在窗口显示前恢复；记录的位置已不在任何显示器上时改为默认位置。完整模式的最大化状态在从清单模式切回时恢复，启动时只恢复位置与尺寸，以免 Windows 在同步原生配色前提前显示窗口。浏览器预览只切换布局。设计依据见设计文档 U7。
- 节点表单修改后立即自动保存本机草稿，按空间、类型、事项和动作隔离，重新打开可恢复。点击“提交”只校验本机表单并立即展示核对页，不等待远端；勾选确认后点击“确认提交并执行”才由后端重新校验远端流程版本、更新字段、核验并推进。提交结果不明时保留草稿与提交标记，阻止直接重复提交。具体范围见 [节点填写与草稿](../backend/docs/节点填写与草稿.md)。

## 范围与限制

列表按来源保存最近同步结果。完整成功后，已不属于该来源的事项移出清单；其他来源仍包含的事项保留。同步失败、分页不完整或条目解析失败时保留已有清单。详情刷新会回写当前状态，列表底部刷新按钮直接同步飞书。排期仅显示原文，不解释未确认的时间单位。
流程动作已在后端实现并用真实凭据测过**只读侧**；写侧尚未由实现侧执行。流程操作默认开启；使用者可按
[写侧验收手册](../backend/docs/写侧验收手册.md) 核对操作步骤；配置中的 `workflow_enabled` 仅控制 CLI。
类型发现与按来源的同步范围已接入桌面 IPC；侧栏类型显示偏好和别名仍单独保存在本机。
来源配置写入、人员字段/角色与自定义关联规则、类型和普通视图查询、完整逻辑字段补全均已实现，见 [工作来源与详情补全](../backend/docs/工作来源与详情补全.md)。没有托盘或 OAuth 登录。

浏览器预览为空态且明确标记，测试样本只存在测试文件中。生产界面不填充演示事项。
